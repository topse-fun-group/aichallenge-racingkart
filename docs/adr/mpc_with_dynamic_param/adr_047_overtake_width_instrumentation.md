# ADR-047: 追い越し幅の内訳をログに出す（P1 の切り分け）

## ステータス
承認済み (Accepted)

P1（コーナー中曲率帯の幅中断）の原因を絞り込むための**計測追加のみ**。
挙動は変更しない。

## コンテキスト

`production-result/analysis_v135_priorities.md` の P1 について、
「突入時の観測量では弁別できておらず仮説が立っていないので、まず `_exit` ログに
将来幅と要求幅を足すのが先」と結論していた。ADR-046 適用後の
`output/20260831-081514`（追い越し 190 件・成功 65 = 34%）で再測した。

### P1 は依然として最大の損失源

```text
|kappa| 0.00-0.05  n= 31  成功 16 (52%)  幅中断 12 (39%)
|kappa| 0.05-0.10  n=  7  成功  0 ( 0%)  幅中断  7 (100%)
|kappa| 0.10-0.16  n= 80  成功 16 (20%)  幅中断 55 (69%)   <- 最大
|kappa| 0.16-0.25  n= 72  成功 33 (46%)  幅中断 20 (28%)
```

ADR-044（寄せ側の物理的下限）を入れても中曲率帯は改善していない。

### 今回見つかった強い信号: 「幅が広い突入ほど全滅する」

```text
突入時 side_w >= 3.5m : n=20  成功  1 ( 5%)  幅中断 19 ( 95%)
突入時 min_w  >= 3.5m : n=17  成功  0 ( 0%)  幅中断 17 (100%)
```

`min_w` 帯ごとに突入→離脱で何が起きたかを見ると、広い帯だけ挙動が違う。

```text
突入 min_w    n  成功  突入sw  離脱sw  崩壊[m/s]  突入|k|  離脱|k|  |k|増  滞在
< 3.0        16    2   2.96   1.90     0.48    0.134   0.131   31%  2.24
3.0-3.5      54   14   3.07   1.82     0.59    0.136   0.140   50%  2.21
>= 3.5       17    0   3.72   1.40     1.30    0.103   0.046    0%  1.72
```

広い突入は **|kappa| が 0.103 → 0.046 と下がる**（コーナー出口へ向かう）方向で、
**崩壊速度が 1.30 m/s と他帯の 2〜3 倍**。17 件すべて失敗している。

全帯で同じ層別をすると、これは中曲率帯だけの現象ではない。

```text
直線   全体 n= 31 成功 52%   min_w>=3.5 n=  9 成功 11%
P1帯   全体 n= 87 成功 18%   min_w>=3.5 n= 17 成功  0%
急     全体 n= 72 成功 46%   min_w>=3.5 n= 17 成功 41%
```

**急コーナーだけが例外**（41%）で、直線と中曲率帯では広い突入が壊滅する。

### なぜ切り分けられないか

`avail_left = (ub - W_WALL) - (e_y_leader + W_MARGIN)` なので、
`min_w` が大きくなる原因は 2 つあり、ログからは区別できない。

1. **その地点のコース幅（`ub - lb`）が広い** → この先で狭まるなら崩壊する
2. **先行車がセンターラインから大きく外れている** → 車がラインへ戻れば崩壊する

崩壊速度 1.30 m/s は 2 の方が説明しやすいが、確証が無い。
**どちらであるかで打つ手が正反対になる**（1 ならコース形状の先読み、
2 なら先行車の横移動予測 = `predict_overtake_widths` の適用範囲）ので、
推測で条件を足すべきではない。

なお `predict_overtake_widths` は `in_tight_corner`（回頭角 120° 未満）のときしか
適用されていない（ADR-034）。上表の「急コーナーだけ例外」と整合する可能性があるが、
これもログに出ていないので確認できない。

## 決定事項

`DrivingState._exit` の遷移ログに 6 項目を追加する。**挙動は一切変更しない。**

```python
            f" lw={ctx.overtake_width_left:.2f} rw={ctx.overtake_width_right:.2f}"
            f" lwf={ctx.overtake_width_left_future:.2f}"
            f" rwf={ctx.overtake_width_right_future:.2f}"
            f" fwd_lat={num(ctx.forward_vehicle_lateral)}"
            f" tight={int(ctx.in_tight_corner)}"
```

| 項目 | 何が分かるか |
|---|---|
| `lw` / `rw` | **合計 `lw + rw` がその地点の実質コース幅**、差が先行車の寄り具合。上記 1 と 2 を分離できる |
| `lwf` / `rwf` | 突入判定が実際に見ていた将来幅。予測が当たっているかを事後に検証できる |
| `fwd_lat` | 先行車の横偏差そのもの（ADR-043 で `StateContext` まで通してある） |
| `tight` | `predict_overtake_widths` が適用されていたかどうか |

出力例:

```text
[follow] exit reason=safe_width to=overtake ... side=right side_w=3.72 min_w=3.72
  lw=1.10 rw=3.72 lwf=1.10 rwf=2.40 fwd_lat=-0.42 tight=0 kappa=+0.103 offset=-2.50
```

この例なら `lw + rw = 4.82`（コース幅は普通）で `rw` に大きく偏っており、
**先行車が左に寄っている（原因 2）**と読める。次の走行でこれを集計すれば、
17/17 失敗している帯がどちらなのか一意に決まる。

### なぜ挙動を変えなかったか

「`min_w >= 3.5` では突入しない」という規則を足せば、実測上は
成功 1 件を失って 36 件の無駄な試行（うち約 30 件が幅中断）を防げる計算になる。
しかし**機序が未確定のまま相関で条件を足すことになる**。

ADR-035（コーナーで要求幅に一律マージン）と ADR-038（追い越し中の速度上限）は
いずれも機序の推定を誤ったまま入れて差し戻しており、ADR-040 では成功「率」で
評価して成功「件数」を落とした。**同じ失敗を繰り返さないため、今回は計測に留める。**

## 未解決事項

1. **P1 の機序は未確定。** 次の走行で `lw + rw` と `fwd_lat` を集計して、
   コース形状か先行車の横移動かを決める。決まり次第、
   - コース形状なら → コリドーを先読み区間の最小で取る
   - 先行車の横移動なら → `predict_overtake_widths` の `in_tight_corner` ゲートを外す
   のどちらかに進む。
2. **dev で rosbag が記録されていない。** `make dev3-rosbag` という Makefile
   ターゲットはあるが、直近の `output/` には rosbag が無い（最後は
   `20260831-025536`、5MB・状態ログ 0 件で解析に使えない）。
   本番 rosbag が唯一の実位置の計測手段という状況が続いている。
3. 横シフトの起点が自車基準（ADR-045 未解決事項 2）。
4. `predict_overtake_widths` の左右符号非対称（ADR-032 から継続）。
5. ADR-042〜047 はいずれも本番未検証。

## 検証

**154 件パス**（挙動不変なので既存テストの回帰確認のみ）。
ログ 1 行を実値で生成して形式を確認済み。

次の `make dev3` で集計する。

| 見るもの | 判定 |
|---|---|
| `min_w >= 3.5` の突入について `lw + rw` の分布 | 他帯より大きければ**コース形状**が原因 |
| 同じく `fwd_lat` の絶対値 | 他帯より大きければ**先行車の横移動**が原因 |
| `lwf` / `rwf` と実際の離脱時 `side_w` | 予測が崩壊を当てられていたか |
| `tight=1/0` 別の成功率 | `predict_overtake_widths` の適用有無が効いているか |

**rosbag を記録した実行があれば併せて共有してほしい。** 先行車の実位置が取れれば
`fwd_lat` の妥当性まで裏が取れる。
