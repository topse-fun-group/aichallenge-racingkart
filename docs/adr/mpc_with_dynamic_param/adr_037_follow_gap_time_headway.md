# ADR-037: 追従の目標車間を速度依存にし、停止距離を通常経路に実装する

## ステータス
**決定 1 は撤回 (ADR-040)。決定 2（停止距離）も撤回 (ADR-043)。本 ADR は全て無効。**
決定 2 は横方向を見ないため、抜き際に横 1.9m 空いた相手へ全制動を掛け、
停止 -> stuck -> recovery -> 後退に落ちる最悪の退行を生んだ。

実測で試行が 370 -> 226 件、成功件数が 139 -> 103 件と落ちた。本 ADR が根拠にした
「詰めるほど追い越しに失敗する」は帯ごとの成功**率**の比較で、母数の少ない帯
（0-3m は 29 件）を過大評価していた。評価は総成功**件数**で行うべきだった。

ADR-028 の**「追い越し幅があるときは `D0_M` まで詰める」を supersede する**。
PD の構造（`v_cmd = v_lead + K_gap*(gap - d_des) + K_v*(v_lead - v_ego)`）は維持する。

## コンテキスト

ADR-036（コーナー内側の見送り）適用後の `output/20260830-230639` で、内側 veto は
狙いどおり効いた。

```text
コーナー突入 311 件  うち内側 0 件 (前回 39%)
  外側 n=311 passed=112 (36%)      ... コーナー成功率 22% -> 36%
recovery 22 件 (前回 66 件)
```

一方で「Follow 時に先行車両と衝突してクラッシュするケースが何回か見られる」という
報告があった。`is_colliding` は publisher が無く一度も立たないため（ADR-030）、
追突は状態ログに現れない。コードを直接読んで原因を特定した。

### 原因 1: 目標車間が速度に依存せず、レース速度では短すぎる

`FollowState.get_adjusted_v_max_mps` の目標車間は 2 値の固定値だった。

```python
d_des = D0_M if ctx.min_forward_overtake_width >= MIN_OVERTAKE_WIDTH_M \
        else FOLLOW_TARGET_DISTANCE_M          # 0.9 m か 1.2 m
```

`D0_M = 0.9 m`（バンパー間）は 25 km/h で **0.13 s ヘッドウェイ**にすぎない。
実測では `safe_width`（`min_forward_overtake_width >= 2.6` を要求）が追い越し突入の
75% を占めており、走行時間の大半でこの 0.9 m 側が選ばれている。

この車間は環境の遅延・ノイズの包絡線の内側にある。

- V2X は 20 Hz、速度は 2 点差分の無平滑（σ≈2.8 m/s）
- 制御は 40 Hz
- AWSIM の減速は −3.0 m/s² 制限

### 原因 2: 接触時の復元力が弱い

バンパーが接触した `gap = 0`、`v_ego = v_lead` で

```text
v_cmd = v_lead + 1.4 * (0 - 0.9) = v_lead - 1.26 m/s
```

先行車比で 1.26 m/s しか落ちない。しかもこれは**速度目標**であり、実際の減速は
`acc = KP*(u[0] - v)` を経てさらに鈍る。追突を止める力になっていない。

### 原因 3: 停止距離が通常の追従経路に実装されていない

`FOLLOW_STOP_DISTANCE_M = 0.8`（「完全停止・ブレーキ閾値、遅延を考慮」）は
定義済みだが、使われていたのは**側方車両の分岐だけ**で、通常の追従経路には無かった。

### 「助走のために詰める」という前提が実測と矛盾している

`D0_M` 分岐のコメントは「追い越せる幅があるうちは D0_M まで詰めて追い越しの助走を
作る」。しかし突入時の中心間距離と結果は逆を示す。

```text
中心間 gap    n    成功率   幅で中断
  0-3 m      29     24%      52%     <- D0_M が作る運用点 (中心間 2.5m)
  3-4 m      81     42%      48%
  4-5 m      83     39%      41%
  5-6 m      23     35%      39%
  6 m 以上   95     33%      22%
```

**詰めるほど追い越しに失敗している。** 目標車間を広げることは追突対策であると同時に、
追い越し成功率にも有利に働く。

## 決定事項

### 1. 目標車間を速度依存にする

```python
FOLLOW_TIME_HEADWAY_SEC = 0.15  # [s]  (初版 0.25 -> 実走で「車間が少し長い」ため短縮)


def follow_target_gap_m(v_ego: float) -> float:
    """追従時の目標バンパー間距離 [m]。速度に比例して広げる。"""
    return max(FOLLOW_TARGET_DISTANCE_M, D0_M + FOLLOW_TIME_HEADWAY_SEC * v_ego)
```

`min_forward_overtake_width` による分岐は**削除する**（上表のとおり前提が否定された）。

| 自車速 | 目標バンパー間 | 中心間 | 初版 h=0.25 | 旧（`D0_M` 固定） |
|---|---|---|---|---|
| 10 km/h | 1.32 m | 2.92 m | 3.19 m | 2.50 m |
| 15 km/h | 1.52 m | 3.12 m | 3.54 m | 2.50 m |
| 20 km/h | 1.73 m | 3.33 m | 3.89 m | 2.50 m |
| 25 km/h | 1.94 m | 3.54 m | 4.24 m | 2.50 m |
| 30 km/h | 2.15 m | 3.75 m | 4.58 m | 2.50 m |

`h = 0.15` は「反応時間 0.15 s（V2X 20 Hz + 制御 40 Hz + 作動）＋ 停止時余裕 `D0_M`」に
対応する。25 km/h なら反応中の走行が 1.04 m、これに `D0_M = 0.9` を足して 1.94 m。
**これ以上詰めると反応時間分を割るので、ここが下限。**
初版の 0.25 は実走で「車間が少し長い」との評価があり短縮した。

レース速度での運用点が、上表で成功率の高い 3〜5 m 帯（39〜42%）に収まる。
低速では `FOLLOW_TARGET_DISTANCE_M` が下限として効く。

### 2. 停止距離を通常の追従経路にも入れる

```python
        if gap <= FOLLOW_STOP_DISTANCE_M:
            return 0.0
```

決定 1 の目標車間なら PD 自体もこの付近で強く絞るので、これは保険。
「危険な車間では止まる」という規則を、ゲインの副作用ではなくコードに書く意味がある。

### 3. ゲインは据え置く

`FOLLOW_K_GAP = 1.4` / `FOLLOW_K_V = 0.5` は変更しない。今回は目標値と下限だけを直し、
ゲインの再調整は実走を見てから判断する。

### 4. ROS パラメータ

`STATE_PARAM_MAP` に `follow_time_headway_sec` を追加。

## 未解決事項

1. **コーナーで残る幅中断（`narrow` 89 件、|kappa| 0.10-0.16 に集中）は原因未特定。**
   突入時の `side_w`・`gap`・`|kappa|`・速度差のいずれも単調に効かず、
   「コーナーが進むとキツくなる」仮説も否定された（きつくなった側の幅中断 45% に対し、
   緩んだ側が 59%）。`_exit` のログに将来幅（`overtake_width_*_future`）と
   要求幅を足さないと切り分けられない。次に着手するならまず計測項目の追加から。
2. **幅が足りているのに追い越さない件。** `follow_path` の見送り
   `not_safe_width_with_enough_distance` 73 件のうち 69 件は `min_w >= 2.6`
   （中央値 3.31、`side_w` 3.26）。うち 42% は `is_slow_leader`（先行車 ≤ 25 km/h）で
   弾かれている。先行車速の中央値が 24.9 km/h と `MIN_OVERTAKE_LEAD_SPEED` の
   真上にあり、閾値が母集団の最頻値に重なっている。
3. `forward_vehicle_gap` が常に 0.0 で `is_ttc_close` が恒真（ADR-027 から継続）。
   本 ADR の PD は `forward_vehicle_distance` から自前計算しているので影響しないが、
   `safe_width` に距離ゲートが無い状態は残る。
4. `corner_overtake` の `inside_width` 判定が有名無実（ADR-036 未解決事項 1）。
5. V2X 速度が 2 点差分・無平滑。`V2XVehicleTracker` の `maxlen=2` を広げるのが先。

## 検証

`test/test_follow_state_gap_pd.py` を更新。**122 件パス**。
`test_wide_corridor_targets_d0_and_closes_the_gap_faster` は
「幅で目標車間が変わらないこと」を確認する形に反転させた。

| ケース | 期待 |
|---|---|
| 目標車間が速度に対し単調増加 | `target(8.0) > target(3.0) > target(0.0)` |
| 低速での下限 | `target(0.0) == FOLLOW_TARGET_DISTANCE_M` |
| 25 km/h のヘッドウェイ | `>= 0.12 s`（`D0_M` を再調整しても効く形で保証） |
| **停止距離の内側** | **`v_cmd == 0.0`（本命）** |
| 停止距離の外側 | 低速でも `v_cmd > 0` |
| 目標車間で速度一致 | `v_cmd == v_lead`（定常偏差なし） |
| 追い越し幅を変える | `v_cmd` が変わらない |
| `FOLLOW_TIME_HEADWAY_SEC` / `FOLLOW_STOP_DISTANCE_M` の書き換え | 呼び出し時に読む |

実走（`make dev3`）は `output/20260830-230639` と比較する。

| 指標 | 20260830-230639 | 期待 |
|---|---|---|
| 目視: Follow 中の追突 | 数回 | 減る（本命） |
| 突入時の中心間 gap 中央値 | 4.4 m | 4 m 前後を維持 |
| gap < 3 m からの突入 | 29 件（成功 24%） | 大きく減る |
| コーナー成功率 | 36% | 維持〜微増 |
| 追い越し試行の総数 | 370 | 大きく減らないこと（**退行の主リスク**） |
| recovery 件数 | 22 | 増えないこと |

**主なリスク**: 車間を広げて追い越しの試行回数自体が減ること。`safe_width` の突入条件は
距離を見ていない（未解決事項 3）ので理屈上は減らないが、実測で確認する。
減った場合は `FOLLOW_TIME_HEADWAY_SEC` を 0.15 前後へ下げて再評価する。

**追記**: 実走の結果、試行回数の減少ではなく「車間が全体的に少し長い」という
評価だったため、事前登録どおり 0.25 -> 0.15 へ短縮した（中心間で 25 km/h 時 -0.7 m）。
