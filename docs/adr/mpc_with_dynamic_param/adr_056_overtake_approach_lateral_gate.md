# ADR-056: 追い越し突入時の速度解放を「横に出きるまで」制動距離で頭打ちにする

## ステータス
**保留 (Deferred)** — 実装は撤回し、作業ツリーは `naito_v1.3.6a` に戻した。

`output/20260901-013930`（C = v1.3.6a + 本 ADR）を `output/20260831-210615`
（B = v1.3.6a 相当）と比較した結果、**dev では検証できないと判明したため。**

**狙った型が B の時点で既に 0 件だった。**

| 衝突の分類 | A: v1.3.6 | B: v1.3.6a | C: +本 ADR |
|---|---|---|---|
| **`overtake` × 横差 < 1.2 m**（本 ADR の狙い） | 2 件 | **0 件** | **0 件** |

周回あたりに正規化すると全指標がわずかに悪化しており、改善の証拠が無い。

| 指標 /周 | B | C |
|---|---|---|
| 試行 | 3.23 | 3.23 |
| 成功 | **1.152** | 1.084 |
| 衝突 | **0.296** | 0.307 |
| 他車由来 | **0.239** | 0.274 |
| recovery | **0.082** | 0.099 |
| 12 km/h 未満 | **7.4%** | 8.1% |

個々は誤差の範囲だが 4 指標が同じ向きで、**dev に直す対象が無い以上、
B → C の差は本 ADR の効果ではなく走行間のばらつき**と判断した。
ADR-054 と同じく、**dev の交通（先行車の 99% が 24.8km/h）では発火しない変更**だった。

狙い自体は実在する（本番の勝ち走行 `1788188497162` でペナルティ 33.4s のうち
21.5s がこの型）。**本番ログで `overtake` 中の接触が再発したら復帰させる。**
判定は本番の「`overtake` 中の接触件数」と「ペナルティ秒数」でしか行えない。

`OvertakeState` の `OVERTAKE_TARGET_SPEED_KMH = 50` の解放に、
**先行車と横方向に離れきるまでの間だけ**制動距離の上限を掛ける。
**解放そのもの・突入条件・幅の門番・中断条件は変更しない。**

## コンテキスト

競争環境で**勝った** `naito_v1.3.6a`（= v1.3.6 + ADR-049 + ADR-054、
`1788188497162`）を検証した。

### ADR-054 は想定どおり動いた（本番で検証済み）

**内側への突入が 0 件 → 7 件、うち 5 件成功（71%）。**
突入時の速度余裕（`cap − forward_v`）は 11.4〜26.0 m/s で、閾値 3.0 に対し十分。
ADR-036 の「内側は成功 7%」は 24 km/h の相手での実測であり、
6〜10 km/h の NPC には当てはまらないという仮説が実証された。

総合成績も 4 走行中の最良だった。

|---|---|---|
| 12 km/h 未満 | 19 / 23 / 27% | **18%** |
| recovery | 3 / 4 / 2 | **1** |
| 衝突 | 3 / 5 / 6 | **3** |
| 壁越え | 0.6 / 0.0 / 0.0 s | **0.0 s** |
| **5 km/h ペナルティ** | 10.2 / 13.2 / 28.5 s | **33.4 s（最悪）** |

### 失敗の型が `follow` の追突から `overtake` の接触に移った

ペナルティ 33.4 s のうち **21.5 s は `overtake` 状態で NPC に接触した 2 件**。
機序は両方同じだった。

```text
t=217.1  車間 3.00m  横差 -0.23m  指令 10.0 -> 50.0 km/h   follow -> overtake
t=217.8  車間 2.00m  横差 +0.06m  指令 50.0
t=218.0  車間 1.00m  横差 +0.25m  指令 50.0               <- 接触、以後 5.0km/h
```

**突入した瞬間に指令が 50 km/h へ解放され、横シフトが立ち上がる前に
まっすぐ前車へ加速している。** 接触時の横方向の離れは 0.25〜0.45 m で、
必要な車幅 1.45 m に遠く届かない。ADR-045 / ADR-050 で測った
「指令 2.1〜2.4 m に対し実測 0.3〜0.6 m」の横方向の権限不足がそのまま出た形。

### 成功と失敗は「横に出きったか」で分かれる

`1788188497162` の追い越し 13 件を、最接近点（車間 0 m）での横差で見る。

```text
成功 (passed)   -3.45 / +2.76 / +2.56 / +1.31 m
接触            -0.14 / +0.25 〜 +0.45 m
```

**成功時は 1.31〜3.45 m、接触時は 0.14〜0.45 m。** 車幅は 1.45 m。

### 保留した ADR-055 では防げない

ADR-055 の上限は `FollowState` にしか掛からない。
制動距離を切っている時間の状態別内訳でも、対象は `overtake` 側にある。

| 走行 | 合計 | `follow_path` | **`overtake`** |
|---|---|---|---|
| v1.3.6a | 18 s | 2 s | **13 s** |
| v1.3.6 | 50 s | 1 s | **25 s** |

## 決定事項

### 横に出きるまでの接近上限

```python
OVERTAKE_LATERAL_CLEAR_M = 1.2   # [m]


def overtake_approach_speed_mps(ctx) -> Optional[float]:
    if (ctx.forward_vehicle_distance is None
            or ctx.forward_vehicle_speed is None
            or ctx.forward_vehicle_lateral is None
            or abs(ctx.forward_vehicle_lateral) >= OVERTAKE_LATERAL_CLEAR_M):
        return None
    return overtake_return_speed_mps(
        ctx.forward_vehicle_distance, ctx.forward_vehicle_speed)
```

`mpc_controller._control` の `OvertakeState` 分岐で
`v_target = min(v_target, approach_cap)` を掛ける。

**式は ADR-041 の `overtake_return_speed_mps` をそのまま再利用する**
（`OVERTAKE_RETURN_BRAKE_MPSS = 2.0` / `FOLLOW_STOP_DISTANCE_M = 0.5` も不変）。
違うのは掛ける条件だけ。新規定数は `OVERTAKE_LATERAL_CLEAR_M` の 1 つ。

`ctx.forward_vehicle_lateral` は `_detect_forward_and_side_vehicles` の
`best_lat = float(y_rel)`（自車座標系の横偏差、左が正）。
`FORWARD_LATERAL_MAX = 3.5` を超えると `None` になるが、
そのときは十分離れているので上限を掛けないのが正しい。

ADR-049 のコーナー速度下限はこの後に `v_target = min(v_target, v_corner)` で
入るため、本上限が上書きされることはない。

### 値の根拠

| 量 | 値 | 根拠 |
|---|---|---|
| 車幅 | 1.45 m | 自車半幅 0.725 × 2 |
| **`OVERTAKE_LATERAL_CLEAR_M`** | **1.2 m** | 成功 1.31〜3.45 / 接触 0.14〜0.45 の間。1.2 なら成功への抑制が 8%、1.45 では 13% |

先行車 10 km/h に対する上限の実値。

| 車間 | 上限 | | 車間 | 上限 |
|---|---|---|---|---|
| 2 m | 10.0 km/h | | 6 m | 24.2 km/h |
| 3 m | 16.8 km/h | | 8 m | 27.5 km/h |
| 4 m | 19.9 km/h | | 10 m（検知端） | 30.2 km/h |

24 km/h の相手なら検知端で 44.2 km/h となり車両上限を超えるので**実質掛からない**。
狙いどおり低速の相手への突入だけに効く。

### ADR-038 との違い（最重要）

ADR-038 は**追い越し中に無条件で**先行車速ベースの上限を掛け、
成功率 46% → 25%・`stuck` 1 → 11 件で撤回した。原因は正のフィードバック
（先行車が減速 → 上限も落ちる → 自車も合わせる → 永久に抜けない）。

本 ADR は

1. **横に出きったら上限が完全に消える。** 脱出経路がある
2. 上限は速度合わせではなく**車間に応じて増える制動距離の式**

実測でも、成功した追い越しへの抑制はサンプルの **8%**（最大 17.6 km/h）に留まり、
接触した 2 件には **21% / 30%** 掛かる。

## 未解決事項

1. **横シフトの起点が自車基準**（ADR-045 未解決事項 2）。
   横差が 0.3〜0.6 m しか出ない根本原因。本 ADR は
   「出られないなら詰めない」という対症であって根治ではない。
2. **幅の門番が `follow` 足止めの残存 36%。** ADR-054 の本番結果が良かったので
   次に効く候補だが、ADR-052 の失敗（幅と中断を同時に緩めた）を繰り返さないこと。
3. ADR-055（保留）— `follow` の追突が再発するなら復帰させる。
4. 側方車の判定に距離下限も後方の除外も無い（`mpc_controller.py:1141-1147`）。
5. 停止に近い相手（NPC は 5〜11% の時間 2 km/h 未満）への接近は検知 10 m では
   間に合わない（35 km/h から 21.4 m 必要）。ADR-055 の論点。

## 検証

**174 件パス**（ADR-056 分 10 件を追加）。

| ケース | 期待 |
|---|---|
| **横差 0.25 m・車間 2 m・先行車 10 km/h** | **上限 10 km/h**（本命。現状は 50 km/h に解放） |
| 横差 1.5 m（出きった） | 上限なし（`None`） |
| 横差ちょうど 1.2 m / 1.19 m | なし / あり（境界） |
| 横差の符号 | 左右対称 |
| 車間 2 m → 6 m | 上限が緩む（速度合わせではないことの確認） |
| 先行車 24 km/h・検知端 | 車両上限超え = 実質無効 |
| 検知端（10 m）の低速相手 | 28 km/h 超（突入直後の全制動を招かない） |
| `forward_vehicle_lateral` / `distance` / `speed` が `None` | 上限なし |
| `OVERTAKE_LATERAL_CLEAR_M` の書き換え | 呼び出し時に読む |

実走は `make dev3-rosbag` の 40 周 A/B。基準は直前の B（`output/20260831-210615`）。
**dev でも突入直後の接近は起きる**ので、ADR-054 と違い dev でも部分的に検証できる。

| 指標 | 基準 | 期待 |
|---|---|---|
| **成功件数 / 試行** | **140 / 393** | **落ちないこと（ADR-038 の失敗の兆候）** |
| **衝突（他車由来）** | **36 (29)** | **減る（本命）** |
| **`stuck` 出口** | **2** | **増えないこと（ADR-038 では 1 → 11）** |
| 12 km/h 未満 | 441 s (7%) | 増えないこと |
| ラップ 中央 | 48.7 s | 維持 |

本番では **ペナルティ 33.4 s**、**`overtake` での接触 2 件 21.5 s**、
**内側突入の成功率 5/7** を基準にする。

**主なリスク**: 抑制しすぎて抜けなくなる（ADR-038 の再来）。
兆候は「成功件数の低下」と「`stuck` 出口の増加」。出ていれば
`OVERTAKE_LATERAL_CLEAR_M` を 1.2 → 0.9 に下げるのが最初の調整点
（車幅の半分強まで出れば解放）。ROS パラメータで調整できる。
