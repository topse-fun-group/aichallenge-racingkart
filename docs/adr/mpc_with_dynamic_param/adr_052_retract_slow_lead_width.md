# ADR-052: ADR-051 を撤回する（幅は blocker ではなかった）

## ステータス
承認済み (Accepted)

**ADR-051（停止・低速の相手には要求幅を 2.6 → 2.0 m に下げる）を全面撤回する。**
`MIN_OVERTAKE_WIDTH_M = 2.6` に戻す。ADR-049 / ADR-050 は維持。

## コンテキスト

ADR-051 を適用した `output/20260831-141034` を、適用前の
`output/20260831-131731` と比較した。**唯一の差分は ADR-051。**

### 明確な退行

| 指標 | ADR-051 前 (131731) | ADR-051 後 (141034) |
|---|---|---|
| 追い越し試行 | 317 | **610** |
| 成功件数 | **105 (33%)** | **115 (19%)** |
| recovery | **23** | **347** |
| うち `overtake` 由来 | 2 | **190** |
| 出口 `stuck` | 3 | **251** |

低速（<10 km/h）の相手に絞ると、より露骨。

| | 試行 | 成功 | `stuck` 出口 |
|---|---|---|---|
| ADR-051 前 | 13 | **11 (85%)** | **0** |
| ADR-051 後 | **290** | 30 (10%) | **241** |

**13 試行・成功率 85% を、290 試行・成功率 10%・stuck 241 件にした。**
成功件数は 105 → 115 とほぼ増えず、recovery だけ 15 倍になった。

### 原因: 幅は blocker ではなかった

`overtake -> recovery (stuck)` に落ちた 183 件（低速の相手）の実測。

```text
gap    中央 1.61 m   <- 車長 1.6m なのでバンパー間ほぼゼロ = 接触
side_w 中央 2.96 m   <- 幅は足りている
d_off  中央 2.13 m   <- 操舵が狙っている横オフセット
e_y    中央 0.29 m   <- 実際に出られた横方向の距離
```

**横に 0.29 m しか出られないうちに停止車へ到達している。** 車幅 1.45 m には足りない。
Pure Pursuit の横ずれは走行距離の 2 乗に比例するので、
**停止した相手には「近づく速さ」に対して「横に出る速さ」が間に合わない。**

要求幅を下げたことは、**実行できない追い越しに突入する許可を与えただけ**だった。
v1.3.5 run2 で 190 s を空費した「停止車を避けずに押し続ける」パターンの再来である。

### ADR-051 の推論のどこが誤っていたか

ADR-051 は「低速の相手ほど成功率が高い（1〜5 km/h で 7/7）」を根拠にした。
しかしその 7 件は**幅が 2.6 m 以上あった、つまり相手が中央から外れていた**ケースで、
「中央にいて幅が 2.32 m しかない相手」とは別の母集団だった。
**選択バイアスのかかった標本から、条件を緩めた先の成功率を外挿してしまった。**

## 決定事項

### ADR-051 を全面撤回する

| 対象 | 内容 |
|---|---|
| 定数 | `OVERTAKE_SLOW_LEAD_MPS` / `OVERTAKE_SLOW_WIDTH_M` を削除 |
| 関数 | `is_slow_lead_overtake()` / `min_overtake_width()` を削除 |
| 突入・門番 19 箇所 | `min_w_req` → `MIN_OVERTAKE_WIDTH_M` |
| `narrow` 中断 | 低速の相手を除外する条件を削除 |
| `mpc_controller.py` | `STATE_PARAM_MAP` の 2 行を削除 |
| テスト | ADR-051 分 9 件を削除（169 → 160 件） |

`MIN_OVERTAKE_WIDTH_M = 2.6` は据え置く（計算値ベースの設計値を尊重）。

## 「中央の停止車」への対応方針

**幅の閾値では解決しない。** 今回の実測がそれを示している。

- 要求幅 2.0 m にしても成功率 10%、241 件が `stuck`
- 実際の blocker は横方向の権限（指令 2.13 m に対し実測 0.29 m）
- 許容上限として挙がった 2.5 m でも、中央の停止車（左右とも 2.32 m）は
  突入条件を満たさない。**狙ったケースには効かないまま副作用だけ受ける**

根治するには**横シフトの起点を自車基準から障害物基準に変える**必要がある
（ADR-045 未解決事項 2）。現状は Hann 窓が `closest_idx`（自車の最近傍点）起点なので、
自車が進むと山も前へ逃げ、自車のすぐ前は常に無シフトのまま。
障害物基準にすれば相手に着く前にオフセットが立ち上がる。
ただし操舵の根幹に触る変更で、通常走行のコーナー追従に影響しうる。

**実競争でこのケースは多くないため、現時点では見送る。**

## 「初期速度が乗っていないときの衝突」

退行前の基準（131731、recovery 23 件）で数えた。

| 事象 | 件数 |
|---|---|
| `overtake -> follow` の直後 4 秒以内に recovery | **2 / 23 (9%)** |
| 直前 6 秒以内に別の recovery を抜けていた | **9 / 23 (39%)** |
| `follow_path` 由来の recovery のうち直前が `recovery -> follow_path` | **14 / 17** |

報告された事象そのもの（追い越し → 追従での衝突）は 2 件と少ない。
一方で「復帰した直後にまた止まる」が 39% あり、そちらの方が大きい。
ただし原因は同じ「障害物を避けきれない」で、`OVERTAKE_SIDE_HOLD_SEC`（ADR-050）や
復帰のクールダウンでは解けない。**横シフトの起点の件と同じ根に帰着する。**

## 未解決事項

1. **横シフトの起点が自車基準**（ADR-045 未解決事項 2）。
   「中央の停止車を避けられない」「復帰直後にまた止まる」の両方がここに帰着する。
   **現時点で最大の未解決項目。**
2. `d_off` がコリドーの想定の半分に潰れている（ADR-050 未解決事項 1）。
3. 通常速度（20+ km/h）の相手は成功率 31%・幅中断 47% のまま。
4. 実測ヨーレートが指令からの期待値の 0.39 倍（ADR-049 未解決事項 2）。
5. ADR-042〜050 / 052 はいずれも本番未検証。

## 教訓

ADR-040（成功「率」で評価して成功「件数」を落とした）に続き、
**条件を緩める変更を、緩める前の母集団の成功率から外挿した**のが今回の誤り。
今後、突入条件を緩める提案は「緩めた先に入ってくる母集団が、
既存の母集団と同じ性質か」を先に確認する。
