# ADR-049: 追い越し中の速度上限に先行車速の下限を入れ、横移動の機序を計測する

## ステータス
承認済み (Accepted)

ADR-033 決定 2（コーナーの速度上限）を `OvertakeState` に限って緩める。
併せて「追い越しで横に出られない」機序の切り分け用の計測を足す（挙動は不変）。

## コンテキスト

`naito_v1.3.6` の本番走行（ログ + rosbag + 動画）を解析した。

```text
周回     81.6 / 45.5 / 48.7 / 48.8 / 77.9 / 48.8 s   合計 351 s
12km/h 未満   68 s (19%)     <- 過去最良 (v1.3.5 run1 は 22%、v1.3.4 は 46-48%)
追い越し 24 件 成功 9 (38%)   recovery は s=103 と s=287 の 2 か所に集中
```

ADR-042〜048 は効いている。報告された 2 点はどちらも実データで再現できた。

### 最大の発見: 追い越しで車体が横に出ていない

rosbag の実位置を `traj_mincurv` 基準の横偏差に直して集計した。

| 量 | 値 |
|---|---|
| 追い越し時の目標横オフセット | **2.10〜2.41 m** |
| 実際に到達した横偏差（18 区間の最大値の中央） | **0.57 m（24%）** |
| `passed` 時の自車と相手の横方向の離れ | **0.03〜0.51 m** |
| 自車の横偏差の全区間レンジ | ±0.72 m |
| **相手 2 台**の横偏差レンジ | ±0.70 m |

**`passed` は横に並んで抜いたのではなく、同一レーン内で前後が入れ替わっただけ。**

道幅が原因ではない。占有格子（`env/final_ver3/occupancy_grid_map.pgm`、
解像度 0.1 m）をレーシングラインの法線方向にレイキャストすると、
**全 351 waypoint で左右とも 5 m 以上が空き**だった。場所は足りている。

### 報告 ①「開始位置付近で左に寄せて左壁に衝突」— 再現した

s ≈ 33 m（スタート直後）。

```text
-0.9s follow_path->overtake (safe_width)  ego=29.65 fwd=24.75 gap=4.85 side=left lw=3.72 rw=1.19
+0.7s overtake  ->follow_path (lost)      ego=0.02      <- 1.6 秒で 29.65 -> 0.02 km/h
+0.9s follow_path->recovery (stuck)
```

29.65 → 0.02 km/h は 5.1 m/s² 相当で、AWSIM の制動上限 −3.0 m/s² を超える。
**制動ではなく衝突。**

### 報告 ②「幅があるのに低速の先行車に合わせて追い越さない」— 機序を特定

ADR-033 決定 2 のコーナー速度上限が `OvertakeState` にも掛かっていた。

```python
if ctx.in_tight_corner:
    v_corner = np.sqrt(self._mpc_cfg.ay_max / (abs(ctx.path_kappa) + 1e-6))
    v_target = min(v_target, v_corner)     # OVERTAKE_TARGET_SPEED_KMH=50 の指令も潰す
```

| \|kappa\| | 上限 | 先行車の実速 |
|---|---|---|
| 0.10 | 19.7 km/h | 約 24 km/h |
| 0.15 | **16.1 km/h** | 約 24 km/h |
| 0.20 | 13.9 km/h | 約 24 km/h |

**コーナーでは上限が先行車の速度を下回るため、追い越しは構造的に不可能。**
実測でも追い越し中の速度は中央 **18.9 km/h**（指令 50 km/h に対して）。
20.4 s 停滞した s = 287 m は `kappa = -0.149` で、上限 16.2 km/h の区間だった。

**先行車がその速度でコーナーを曲がれている以上、同じ速度は物理的に出せる。**

## 決定事項

### 1. 追い越し中は速度上限を先行車速より下げない

`mpc_controller.py` の `_control`。

```python
                if (isinstance(current_state, states.OvertakeState)
                        and ctx.forward_vehicle_speed is not None):
                    v_corner = max(
                        v_corner,
                        ctx.forward_vehicle_speed
                        + states.OVERTAKE_CORNER_SPEED_MARGIN_MPS)
                v_target = min(v_target, v_corner)
```

`OVERTAKE_CORNER_SPEED_MARGIN_MPS = 2.0`（既存定数）を再利用。新規定数は増やさない。

| 条件 | 挙動 |
|---|---|
| 追い越し中でない | **完全に不変**（ADR-033 決定 2 の狙いはそのまま） |
| 前方車を検知していない | 不変 |
| 追い越し中・先行車 24 km/h | 上限 16.1 → **31.2 km/h** |
| 追い越し中・先行車 10 km/h | 上限 16.1 → **17.2 km/h**（遅い相手なら上限も低いまま） |

上限は「先行車速 + 2.0 m/s」で頭打ちなので、`OVERTAKE_TARGET_SPEED_KMH = 50` まで
解放するわけではない。**相手が出せている速度に自分も合わせる**という意味づけ。

### 2. 横に出られない機序を確定させる計測（挙動不変）

**指令 2.41 m に対し実測 0.57 m の原因は未確定。** 候補が 3 つある。

1. `d_offset` が壁クランプ `clip(target_offset, lb + 1.225, ub - 1.225)` で縮んでいる
2. 先読み点の重み `weight` が小さい位置に落ちている
3. 操舵指令が実現していない（実測ヨーレートは指令からの期待値の **0.39 倍**）

`_compute_waypoint_shift_pure_pursuit_control` の中で採用した値を保持し、
`StateContext.shift_diag` 経由で `_exit` ログに出す。

```text
d_off=+2.40 w=0.95 alpha=+21.3 steer=+8.2 e_y=+0.57
```

| 項目 | 判定できること |
|---|---|
| `d_off` | クランプ後の実効オフセット。2.4 前後なら候補 1 は否定 |
| `w` | 採用点の Hann 重み。1.0 に近ければ候補 2 は否定 |
| `alpha` / `steer` | 幾何どおりの舵角が出ているか。出ていれば候補 3（実現率）に絞れる |
| `e_y` | 自車の横偏差。指令への追従度そのもの |

ADR-047 → ADR-048（計測 → 次走行で機序確定 → 修正）と同じ進め方。
**機序が確定するまで操舵側は触らない。**

## 優先順位（本番分析の全体）

| 順位 | 項目 | 根拠 | 本 ADR |
|---|---|---|---|
| **P0** | 追い越し中の速度上限が先行車速を下回る | s=287 で 20.4 s 停滞、追い越し中の速度 中央 18.9 km/h | 決定 1 |
| **P0'** | 追い越しで横に出られない | 指令 2.41 m / 実測 0.57 m、`passed` の横差 0.03〜0.51 m | 決定 2（計測） |
| P1 | スタート直後（s ≈ 33 m）の衝突 | 1.6 秒で 29.65 → 0.02 km/h | P0' 次第 |
| P2 | 停滞 2 件（s=103 で 21.4 s、s=287 で 20.4 s） | いずれも `stuck` → `recovery` | s=287 は決定 1 で解消見込み |
| P3 | 左突入 25% vs 右 50% | 各 12 件 | 触らない |

**P1 と P3 を単独で直さない理由**: 左を選んだ突入のうち「狭い側を選んだ」ケースは
**0 件**（ADR-044 の物理的下限は機能している）。左右差も各 12 件で、
同一コードの走行間ばらつき（成功率で 8 ポイント、34% ↔ 42%）に埋もれる。
**横に出られないという P0' が解決しない限り、左右どちらでも接触は起きる。**

## 未解決事項

1. ~~**P0'（横に出られない）は未解決。**~~ **ADR-050 で決着。**
   操舵は追従できている（`d_off` と `e_y` の符号一致 94%、誤差 中央 0.73 m）。
   問題は指令側で、壁クランプが**先読み点の** waypoint 境界で効き、
   `d_off` が中央 1.04 m に潰れていた（式の想定は 2.22 m）。
   判断は先行車位置の幅、操舵は先読み点の幅と、別の場所を見ている。
   ただし有効な修正は見つかっておらず、ADR-050 の未解決事項 1 へ引き継いだ。
2. 実測ヨーレートが指令からの期待値の 0.39 倍。`steering_tire_angle_gain: 1.5`（内部）と
   `steering_tire_angle_gain_var: 1.639`（出版時）の二段ゲインがあり、
   出版値の最大 145.6° は Recovery の舵角上限 1.55 rad × 1.639 = 145.6° と一致する。
   追い越し経路の内部上限 0.55 rad は出版時 51.6° になる。この二段構成が
   意図どおりか未確認。
3. 横シフトの起点が自車基準（ADR-045 未解決事項 2）。
4. dev で rosbag が記録されていない。**今回の解析は本番 rosbag に全面的に依存した。**
   `make dev3-rosbag` を使えば dev でも同じ解析ができる。

## 検証

**154 件パス**（決定 1・2 とも `_control` / 診断で、状態機械の挙動は不変）。

決定 1 は数値で確認した（上表）。決定 2 はログ 1 行を実値で生成して形式を確認した。

実走は ADR-040 の基準（成功件数 → 試行回数 → 低速時間 → 成功率）で見る。

| 指標 | v1.3.6 本番 | 期待 |
|---|---|---|
| **追い越し中の速度 中央** | **18.9 km/h** | **先行車速（約 24 km/h）を下回らない** |
| 成功件数 / 試行 | 9 / 24 (38%) | 試行維持で成功増 |
| 12 km/h 未満の時間 | 68 s (19%) | 減る |
| s ≈ 287 m の停滞 | 20.4 s | 消える |
| 到達した横偏差 | 0.57 m | この時点では改善しなくてよい。**`d_off` / `w` / `steer` / `e_y` で機序が確定すること** |
| ラップ中央 | 48.7 s | 維持〜短縮 |

**主なリスク**: 決定 1 でコーナーの速度上限が上がるため、追い越し中に外へ膨らむ
可能性がある。上限は「先行車速 + 2.0 m/s」で頭打ちで、相手が曲がれている速度が
基準なので過大にはならないと判断するが、`overtake` からの `stuck` / `recovery` が
増えていないかを確認する。
