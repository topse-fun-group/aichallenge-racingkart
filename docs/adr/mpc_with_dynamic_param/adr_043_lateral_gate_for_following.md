# ADR-043: 横に離れた相手を追従対象から外す（停止→Recovery バグの修正）

## ステータス
承認済み (Accepted) — ただし**解除の境界は ADR-046 で遷移帯に変更**。
段差のままだと境界の直下 17.5km/h / 直上 35.0km/h と跳び、V2X の横位置ノイズで
KP=100 の実質バンバン制御が全制動と全開を往復していた。ゲート値 1.7m は不変。

**ADR-037 決定 2（追従経路の停止距離ルール）を撤回する。**
併せて、追従して減速するかどうかの横方向ゲートを新設する。

## コンテキスト

本番動画で「急カーブのインをきれいに抜いている最中に、先行車に近づいた瞬間
車両が停止し、Recovery に遷移して後退。その間に後続に抜かれて負ける」という
報告。複数の動画で再現していた。

`naito_v1.3.5` の rosbag（odometry + V2X 位置）で再現できた。

### 実データ（recovery 突入の前後、`kappa = -0.205` の急カーブ）

自車の進行方向を基準にした相手（d3）の位置。

```text
  -3.0s  自車 24.9km/h   前後 +6.58m  横 -0.61m
  -2.0s  自車 15.8km/h   前後 +0.84m  横 +2.02m
  -1.5s  自車  9.7km/h   前後 -0.98m  横 +1.86m   <- 相手はもう後ろ。横も 1.86m クリア
  -1.0s  自車  3.8km/h   前後 -1.04m  横 +1.74m
  -0.5s  自車  0.0km/h                            <- 完全停止
  +0.5s  自車 -1.2km/h                            <- Recovery で後退
```

状態遷移ログ:

```text
[follow_path] -> follow   ego_v=24.88 forward_v=6.92 gap=4.92 kappa=-0.205
[follow]      -> recovery (stuck)  2.87s 後  ego_v=0.00
```

**抜き終えて横に 1.86 m 空いている相手に対して、24.9 km/h から停止していた。**

### 原因 1: 停止ルールが横方向を見ていない

ADR-037 決定 2 で入れた

```python
if gap <= FOLLOW_STOP_DISTANCE_M:   # gap = forward_vehicle_distance - VEHICLE_LENGTH
    return 0.0
```

の `forward_vehicle_distance` は**経路沿いの中心間距離**で、横方向の離れを一切
考慮しない。追い越しで横に出ていく途中、相手が前方コーン（±45°）の端に来た
瞬間に距離が 2.1 m を切り、横に 1.9 m 空いていても発火する。
`KP = 100` で実質バンバン制御なので、その瞬間に全制動が掛かる。

### 原因 2: 停止ルールを消しても車間 PD 自体が止める

撤回後の指令速度を実測値で計算すると:

```text
自車 24.88km/h / 先行車 6.92km/h
  中心間 6.61m -> 18.7 km/h
  中心間 4.92m -> 10.1 km/h
  中心間 3.00m ->  0.5 km/h
  中心間 2.10m ->  0.0 km/h
```

ダンピング項 `FOLLOW_K_V * (v_lead - v_ego)` が自車 24.9 / 先行車 6.9 km/h では
**−2.50 m/s** になり、それだけで指令がゼロへ落ちる。

**本質は「横に離れている車を追従対象として扱っていること」。**

前方検知には既に横ゲート `FORWARD_LATERAL_MAX = 3.5 m` があるが、
接触するのは車幅 1.45 m（自車半幅 0.725 + 相手半幅 0.725）未満のときで、
3.5 m は減速判断には広すぎた。

## 決定事項

### 1. 停止距離ルールを撤回する

`FollowState.get_adjusted_v_max_mps` から `if gap <= FOLLOW_STOP_DISTANCE_M: return 0.0`
を削除。撤回した旨をコメントで残す。

`FOLLOW_STOP_DISTANCE_M` 自体は `overtake_return_speed_mps`（ADR-041）で
使い続けるので残す。

### 2. 減速判断に専用の横ゲートを設ける

```python
FOLLOW_LATERAL_CLEAR_M = 1.7   # [m] これ以上横に離れていれば追従対象にしない

# get_adjusted_v_max_mps の先頭
if (ctx.forward_vehicle_lateral is not None
        and abs(ctx.forward_vehicle_lateral) >= FOLLOW_LATERAL_CLEAR_M):
    return VEHICLE_V_MAX / 3.6
```

1.7 m は車幅 1.45 m に 0.25 m の余裕を足した値。
`forward_vehicle_lateral` が `None`（横偏差が取れない）ときは従来どおり追従する。

**検知側の `FORWARD_LATERAL_MAX = 3.5 m` は変更しない。** 追い越しの判断
（コリドー幅・突入条件）にはその広さが要る。検知は広く、減速は狭く。

### 3. 横偏差を StateContext まで通す

`_detect_forward_and_side_vehicles` は既に各車の `y_rel` を計算しているので、
最近傍の前方車のものを `best_lat` として返し、`forward_vehicle_lateral` に載せる。
戻り値が 7 要素から 8 要素になる以外、検知ロジックは変更なし。

### 修正後の挙動（本番の実測値をそのまま入れた場合）

```text
自車 24.88km/h / 先行車 6.92km/h
  中心間 6.61m  横 -0.61m -> 18.7 km/h   同一レーン -> 追従
  中心間 4.92m  横 -0.61m -> 10.1 km/h   同一レーン -> 追従
  中心間 2.10m  横 +1.86m -> 35.0 km/h   横クリア -> 追従しない  <- バグ発生点
  中心間 2.10m  横 +1.00m ->  0.0 km/h   同一レーン -> 追従 (正しい)
```

## 未解決事項

1. **V2X 速度ノイズ（ADR-042）も同じ場面に効いていた可能性がある。**
   d3 の 2 点差分推定は 0〜28.8 km/h まで振れており、`v_lead` が一瞬 0 と
   読まれれば PD の目標も 0 になる。ADR-042 と本 ADR の両方が要る。
2. 将来幅予測が効かない理由は未特定（ADR-042 未解決事項 1）。
3. コーナー |kappa| 0.10-0.16 の幅中断 80%。
4. コリドー幅 `avail_*` は自車の幅を引いていない。
5. `is_colliding` が一度も立たず、接触回数を直接計測する手段が無い。
