# ADR-039: ADR-038 を撤回し、停止している先行車は内側 veto の例外にする

## ステータス
承認済み (Accepted)

**ADR-038（追い越し中の接近速度上限）を撤回する。**
ADR-036（コーナー内側の見送り）に停止車の例外を追加する。
ADR-037 は**決定 2（停止距離）のみ維持**（決定 1 は ADR-040 で撤回）。

## コンテキスト

`naito_v1.3.4` の本番 2 走行のログと、そこから加えた変更（ADR-037 / ADR-038）の
dev 走行を突き合わせた。**本番で初めて見えた問題と、dev で見落としていた退行**の両方があった。

### 本番の周回タイム — ロスの大半は「止まっている時間」

```text
run A (…4464774)  69.7 / 57.7 / 38.9 / 145.1 / 66.9 / 53.0 s   6周
run B (…6286959) 132.4 / 48.7 / 117.7 /  82.8 / 52.4 s         5周
```

ベストは 38.9 s。にもかかわらず 145 / 132 / 118 / 83 s の周が混ざる。
clean lap を 45 s とすると run A だけで約 160 s を失っている計算になる。

ADR-036 の内側 veto は本番でも設計どおり効いていた（**コーナー突入の内側 = 0 件**）。

### 問題 1: 停止車の前で内側 veto がデッドロックする

run B のログ生値。

```text
kappa=-0.086 (右コーナー → 内側=右)  side=right  side_w=4.47  min_w=4.47  forward_v=0.00
```

**内側に 4.47 m（`MIN_OVERTAKE_WIDTH_M = 2.6` の 1.7 倍）空いていて、
先行車は完全停止**しているのに、veto が追い越しを禁止する。

```text
+0.0s  follow      -> recovery   (stuck)
+4.6s  recovery    -> follow_path(returned)                       gap=2.93 fwd_v=0.00
+4.6s  follow_path -> follow     (not_safe_width_with_enough_distance)
+6.9s  follow      -> recovery   (stuck)                          gap=1.50 fwd_v=0.00
+8.1s  recovery    -> follow_path(returned)
...   約 3s 周期で 10 回反復
連続 30 イベント / 41.8s   (走行 531.8s の 8%)
```

veto の根拠は「コーナーが進むにつれて**先行車の動き**とコース形状で内側が閉じる」こと。
**動いていない相手には当てはまらない。**

これは以前「十分な追い越し幅があるのに追い越さない」として報告され、優先度低として
保留していた現象と同一。本番では 8% のロスだった。dev で軽く見えたのは、
3 台とも同じ挙動で完全停止する相手が出にくいためである。

### 問題 2: ADR-038 の接近速度上限が追い越しを壊していた

dev の 2 走行で ADR-038 と `FOLLOW_TIME_HEADWAY_SEC` 0.25→0.15 だけが差分。

| 指標 | 002141（ADR-037 まで） | 011757（+ADR-038, h=0.15） |
|---|---|---|
| 追い越し | 226 件 成功 **103 (46%)** | 211 件 成功 **53 (25%)** |
| コーナー成功 / 幅中断 | **49% / 29%** | **27% / 52%** |
| 直線成功 | 29% | 16% |
| recovery | **5 件** | **21 件** |
| overtake の `stuck` 出口 | **1 件** | **11 件** |
| 突入時 中心間 gap 中央 | 5.31 m | 5.12 m |

突入 gap がほぼ動いていないので `h` の変更は主因ではない。**ADR-038 が原因。**

機序: `stuck` 11 件の突入時 gap は 2.76 m、先行車速 24.2 km/h。
追い越し中に先行車が減速すると上限が連動して崩れる。

```text
上限値 (中心間距離ごと)
  先行車  0km/h: 2.5m-> 2.3km/h  3.0m-> 5.6km/h  4.0m-> 9.1km/h
  先行車  5km/h: 2.5m-> 7.3km/h  3.0m->10.6km/h  4.0m->14.1km/h
  先行車 25km/h: 2.5m->27.3km/h  3.0m->30.6km/h  4.0m->34.1km/h
```

**先行車が減速 → 上限が崩壊 → 自車も減速 → 並んで停止 → stuck** という正帰還。
横に出て抜けるべき場面で、自車が先行車に速度を合わせに行っていた。

ADR-038 の想定は「まだ真後ろにいる間だけ絞り、横に出れば前方コーンから外れて
上限は外れる」だったが、**実際には追い越し中も相手がコーン内に残り続ける**。
「突入距離の中央値ではほとんど制限しない」という見積りも、
相手が減速する状況を考慮しておらず不十分だった。

## 決定事項

### 1. ADR-038 を撤回する

| ファイル | 削除するもの |
|---|---|
| `states.py` | `SAFE_APPROACH_BRAKE_MPSS`、`safe_approach_speed_mps()` |
| `mpc_controller.py` | `OvertakeState` の `v_target` 直後の `min(..., safe_approach_speed_mps(...))` |
| `mpc_controller.py` | `STATE_PARAM_MAP` の `safe_approach_brake_mpss` |
| `test/test_follow_state_gap_pd.py` | 「追突回避の速度上限」節 9 件 |

追い越し中断後の追突対策は、**ADR-037 の停止距離**
（`gap <= FOLLOW_STOP_DISTANCE_M` で `v_cmd = 0`）が `FollowState` 側で担う。
撤回後もそこは残るので、追突対策そのものが無くなるわけではない。

### 2. 停止・徐行している先行車は内側 veto の例外にする

`is_inside_corner_overtake()` の曲率判定の直後に 1 ブロック追加するだけ。
**既存の判定ロジックには触らない。**

```python
    lead = ctx.closest_forward_vehicle_speed
    if lead is not None and lead < FOLLOW_LEADER_MOVING_MPS:
        return False
```

`FOLLOW_LEADER_MOVING_MPS = 0.5`（既存定数、0.5 m/s = 1.8 km/h）をそのまま使い、
新規定数は増やさない。速度源は既存の `forward_vehicle_stop` ブロックと同じ
`closest_forward_vehicle_speed` に揃えてある。

`None`（相手の速度が取れていない）のときは従来どおり veto する。安全側。

本番のデッドロック地点はこれで `forward_vehicle_stop` が発火する:
`lead_speed < 1.0/3.6` ✓、`min_forward_overtake_width = 4.47 >= 2.6` ✓。

### 3. ADR-037 は維持する

> **訂正 (ADR-040)**: この判定は誤りだった。突入 gap の中央値が動いていないことだけを
> 見て「副作用なし」としたが、**試行回数が 370 -> 226 件、成功件数が 139 -> 103 件**と
> 落ちていた。目標車間の拡大は ADR-040 で撤回し、停止距離だけを残した。

## 未解決事項

本番ログで新たに見えたもの。

1. **本番では直線の追い越し成功率が 11〜12%**（dev は 29〜46%）。
   dev は同一車両 3 台だが本番の相手は速度域が違う。失敗は `lost`（相手が離れる）が中心。
2. **突入の 37〜41% は自車より速い相手に仕掛けている**（相対速度が負）。
   成功率 17〜18% で全体（20〜27%）より低い。`safe_width` は
   `is_slow_leader`（絶対速度 25 km/h 以下）しか見ておらず**相対速度ゲートが無い**。
   `is_ttc_close` は `forward_vehicle_gap == 0.0` により恒真（ADR-027 から継続）。
   ここが次の候補。
3. コーナーの `narrow` 中断は依然として最大の失敗要因。突入時の観測量では
   弁別できておらず、`_exit` ログへの将来幅・要求幅の追加が先（ADR-037 未解決事項 1）。
4. run A の 28.2 s 停止（`gap=None`・|k|=0.143）は前方車なしの壁での停止。
   コーナー速度上限がヘアピンに掛かっていない件（ADR-033 決定 2）が残っている。
5. **追突回数を直接計測する手段が無い。** `is_colliding` は
   `/aichallenge/pitstop/condition` に publisher が無く一度も立たないため、
   遷移距離と目視でしか測れない。この計測手段の欠如が一連の調査で最も効いている制約。

## 検証

`test/test_follow_state_gap_pd.py` から 9 件削除、`test/test_overtake_corner.py` に
6 件追加。**128 件パス**。

| ケース | 期待 |
|---|---|
| **停止した先行車・コーナー内側** | **veto しない**（本命の回帰防止） |
| 徐行（`FOLLOW_LEADER_MOVING_MPS` 未満）の先行車・内側 | veto しない |
| 閾値超の先行車・内側 | 従来どおり veto する |
| `closest_forward_vehicle_speed` が `None` | 従来どおり veto する |
| `FOLLOW_LEADER_MOVING_MPS` の書き換え | 呼び出し時に読む |
| **本番の再現**（`kappa=-0.086`, 右 4.47m, `lead=0`, `gap=2.91`） | 内側と判定されるが例外が効き、`overtake` へ |
