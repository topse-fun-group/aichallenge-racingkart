# ADR-048: 将来幅の予測を撤回する（P1 の原因は予測そのものだった）

## ステータス
承認済み (Accepted)

**ADR-034 の `predict_overtake_widths` の適用を撤回する。**
ADR-032 系の「将来幅で寄せ側を採点する」という路線はこれで終了。

## コンテキスト

ADR-047 で `_exit` ログに `lw` / `rw` / `lwf` / `rwf` / `fwd_lat` / `tight` を
追加した。その最初の走行 `output/20260831-084001`（追い越し 199 件・成功 83 = 42%）で
P1（コーナー中曲率帯の幅中断）の原因が決着した。

### まず、前回の「幅が広い突入は全滅」は再現しなかった

ADR-047 のコンテキストで挙げた `min_w >= 3.5` の信号（前走行で P1 帯 17 件中 0 成功）は、
今回 43 件中 18 成功（42%）で**全体と同じ**だった。n=17 の相関はノイズだった。

**同一コードでの走行間のばらつきは成功率で 8 ポイント**（34% → 42%）ある。
単一走行・小標本の相関で条件を足さなかった判断は正しかった。

### 決着: 予測が適用されていた突入だけが壊滅していた

`tight` は `predict_overtake_widths` が適用されたかどうかを示す。

```text
tight=0: n=135  成功 72 (53%)  幅中断 45 (33%)
tight=1: n= 64  成功 11 (17%)  幅中断 39 (61%)
```

曲率との交絡を排除しても効果は残る。**同じ `|kappa| 0.10-0.16` 帯で 3 倍の差**:

```text
|kappa| 帯     tight=0                          tight=1
0.10-0.16     n=26 成功 13 (50%) 幅中断 46%     n=56 成功  9 (16%) 幅中断 68%
0.16-0.25     n=76 成功 45 (59%) 幅中断 18%     n= 7 成功  2 (29%) 幅中断  0%
```

### なぜ壊れていたか: 予測が縮小を常に誇張する

離脱理由ごとに「突入時の寄せ側の幅」と「そのとき予測していた将来幅」を並べる。

```text
出口           n   突入 side_w   予測 side_wf   予測の縮小   実際の離脱 sw
narrow        30      3.04         0.55        2.59         2.01
lost          13      3.11         0.99        2.12         0.00
passed        11      3.27         1.16        1.98         0.00
hard_narrow    9      3.69         1.18        2.50         1.40
```

**成功例も含めて全ケースで「2.0〜2.6 m 縮む」と予測している。**
予測値と実際の離脱時の幅の誤差は**中央 −1.09 m**、
**50% のケースで実際より 1 m 以上小さく**見積もっていた。

原因は式の 2 つの前提。

```python
T = OVERTAKE_PREDICT_HORIZON_SEC          # 2.0 s
d = lead_speed * sin(hd) * T + 0.5 * OVERTAKE_PREDICT_LAT_ACCEL_MPSS * T**2
```

1. **ホライズンが長すぎる。** 実際の追い越しの滞在時間は中央 **1.60 s**
   （`passed` に限れば **1.15 s**）で、2.0 s 先まで見る意味がない。
2. **加速度項だけで 1.20 m。** さらに先行車 25 km/h・`heading_diff` 10° なら
   `d = 3.61 m` と、コリドー全体より大きい縮小を出す。

先行車は自分のレーシングラインを追っているだけで、瞬間的な `heading_diff` が
2 秒間そのまま続くわけではない。**「先行車の横速度を一定として外挿する」という
仮定が成り立っていなかった。** ADR-034 は「グローバル直線外挿」の破綻を経路相対で
直したが、外挿そのものの仮定は残っていた。

実測の縮小率は 1.13〜1.34 m/s だが、これは**自車が横に動くことによる見かけの縮小**も
含む。先行車の横移動だけを 2 秒外挿する式では説明できない量を予測していた。

## 決定事項

### 将来幅の予測を止め、将来幅 = 現在幅 にする

`mpc_controller.py` の `_build_state_context`。

```python
        left_wf, right_wf = left_w, right_w
```

`if in_tight_corner:` の分岐ごと削除する。これで

- `resolve_overtake_side` の `min(now, future)` が `min(now, now)` に退化し、
  **「現在幅が広い側」という安定した判定**に戻る（ADR-044 の物理的下限はそのまま効く）
- `future_width_overtake` の `future_w >= MIN` は `now_w >= MIN` と同義になり、
  この枝は `safe_width` の部分集合として無害に残る

`predict_overtake_widths` 関数と、そのユニットテストは**式の記録として残す**
（docstring に撤回と実測を明記）。呼び出しだけを外した。

`ctx.in_tight_corner` は速度上限（ADR-033 決定 2）とログの `tight` で引き続き使う。

### 期待される効果（実測への当てはめ）

`tight=1` の 64 件が `tight=0` と同じ成功率（53%）になれば、
成功件数は 11 → 34 件、全体で **83 → 106 件（42% → 53%）**。

## 未解決事項

1. **走行間のばらつきが成功率で 8 ポイントある。** 単一走行・小標本での判断は
   今後も避ける。`tight=0/1` の比較は同一走行内の対照なのでこの影響を受けない。
2. **`|kappa| 0.05-0.10` は依然として 0/3。** 標本が小さく未評価。
3. 横シフトの起点が自車基準（ADR-045 未解決事項 2）。
4. `predict_overtake_widths` の左右符号非対称（ADR-032 から継続）。
   撤回により実害は無くなったが、式を復活させるなら先に直す必要がある。
5. dev で rosbag が記録されていない（ADR-047 未解決事項 2）。
6. ADR-042〜048 はいずれも本番未検証。

## 検証

**154 件パス**（`predict_overtake_widths` のテストは式の記録として残しているので、
呼び出しを外しても通る）。

実走（`make dev3`）は ADR-040 の基準（成功件数 → 試行回数 → 低速時間 → 成功率）で見る。

| 指標 | 20260831-084001 | 期待 |
|---|---|---|
| **成功件数** | **83 / 199 (42%)** | **106 前後 (53%) へ** |
| 試行回数 | 199 | 維持（突入条件は変えていない） |
| `|kappa| 0.10-0.16` の成功率 | 27% | 50% 前後へ（`tight=0` の水準） |
| 幅中断 (`narrow` + `hard_narrow`) | 84 | 減る |
| 直線 (`|kappa| < 0.05`) の成功率 | 45% | 維持（元から `tight=0`） |
| ログの `lwf` / `rwf` | `lw` / `rw` と乖離 | **`lw` / `rw` と一致する**（撤回の確認） |

**主なリスク**: 将来幅という「閉じる側を選ばない」拒否権が無くなるので、
コーナーで閉じつつある側を選ぶケースが戻る可能性がある。ただし
ADR-044 の物理的下限（`OVERTAKE_HARD_ABORT_WIDTH_M = 1.5 m`）が残っており、
実測では予測ありの方が 3 倍悪かったので、拒否権の価値は負だったと判断する。
