# ADR-046: 追従解除の横方向ゲートを段差から遷移帯にする

## ステータス
承認済み (Accepted)

ADR-043 で入れた「横に離れた相手は追従対象にしない」ゲートの**境界の段差**を消す。
判定の意味づけ（`FOLLOW_LATERAL_CLEAR_M = 1.7 m` で解除）は変えない。

## コンテキスト

ADR-044（寄せ側の下限・復帰の符号）と ADR-045（追い越しの先読みを実速度基準）の
実走後、「前の車に衝突したり、Overtake から Follow に遷移して衝突する回数が
少し増えた気がする」という報告があった。

### 増加は測定では確認できなかった

`make dev3` の 4 走行を状態ログで比較した。

| 走行 | 試行 | 成功 | 成功率 | recovery | うち `overtake` 由来 | うち `follow` 由来 |
|---|---|---|---|---|---|---|
| ADR-044/045 前 (021425) | 148 | 60 | 41% | 4 | 0 | 3 |
| 中間 (040326) | 479 | 200 | 42% | 8 | 3 | 2 |
| 直近 1 (071945) | 70 | 22 | 31% | 17 | 0 | 1 |
| 直近 2 (073411) | 211 | 82 | 39% | 7 | 3 | 3 |

「抜き際に前車がどこにいるか」（`narrow` / `hard_narrow` 離脱時の中心間距離）は
**むしろ改善している**。

| 走行 | n | 中央 | 最小 | < 2.5 m の割合 |
|---|---|---|---|---|
| ADR-044/045 前 | 56 | 4.08 m | 1.36 m | **21%** |
| 直近 2 | 87 | 4.14 m | 1.66 m | **13%** |

`follow` 由来の recovery も 3 / 2 / 1 / 3 で横ばい。
**状態ログで測れる範囲では、衝突の増加は確認できなかった。**

（dev の `output/` には rosbag が無く、本番のように実位置から接触を数えることが
できない。`is_colliding` も立たないので、これ以上の直接計測手段が無い。）

### ただし確認中に実害のある欠陥が見つかった

ADR-043 のゲートは**段差**だった。

```python
if (ctx.forward_vehicle_lateral is not None
        and abs(ctx.forward_vehicle_lateral) >= FOLLOW_LATERAL_CLEAR_M):
    return VEHICLE_V_MAX / 3.6
```

抜き際の典型（中心間 2.5 m / 自車 25 km/h / 先行車 20 km/h）での指令速度:

```text
  横 1.69m -> 17.5 km/h
  横 1.71m -> 35.0 km/h      <- 17.5km/h の跳び
```

縦方向は `acc = KP * (u[0] - v)` で **`KP = 100` は実質バンバン制御**なので、
**V2X の横位置ノイズが境界を跨ぐたびに全制動と全開が往復する。**
抜き際の挙動が乱れる原因になり、報告された症状の regime と一致する。

## 決定事項

### 解除を `FOLLOW_LATERAL_BLEND_M` の帯で滑らかにする

```python
FOLLOW_LATERAL_BLEND_M = 0.3   # [m]

v_free = VEHICLE_V_MAX / 3.6
release = clip((|lat| - (FOLLOW_LATERAL_CLEAR_M - FOLLOW_LATERAL_BLEND_M))
               / FOLLOW_LATERAL_BLEND_M, 0.0, 1.0)
if release >= 1.0:
    return v_free
...車間 PD...
return v_cmd + release * (v_free - v_cmd)
```

**帯はゲートの下側 `[1.4, 1.7]` に置く。** こうすると

- ADR-043 が直した本番ケース（横 1.86 m で停止 → recovery）は**完全解除のまま**保たれる
- 物理的な接触幅 1.45 m（自車半幅 0.725 + 相手半幅 0.725）を帯が挟む形になる
- 段差だけが消える

修正後（同じ条件）:

```text
  横 1.30m -> 17.5 km/h      帯の外。従来どおり車間 PD のまま
  横 1.40m -> 17.5 km/h      帯の下端
  横 1.45m -> 20.4 km/h      接触幅。これ未満でしか接触しない
  横 1.55m -> 26.3 km/h
  横 1.65m -> 32.1 km/h
  横 1.70m -> 35.0 km/h      完全解除
  横 1.86m -> 35.0 km/h      本番ケース (ADR-043) は不変
```

帯を**上側** `[1.7, 2.0]` に置く案も検討したが、本番ケース（1.86 m）が
部分解除（18.6 km/h）に落ちて ADR-043 の修正が部分的に戻ってしまうので採らなかった。
ユニットテストがこの退行を捉えたので、実装中に方針を修正した。

`FOLLOW_LATERAL_CLEAR_M = 1.7` は据え置き。`STATE_PARAM_MAP` に
`follow_lateral_blend_m` を追加。

## 未解決事項

1. **dev では接触を直接計測できない。** `output/` に rosbag が無く、
   `is_colliding` も立たない。本番 rosbag が唯一の直接計測手段になっている。
   dev の実行に rosbag 記録を足せれば、以降の「衝突が増えた気がする」を
   毎回数値で答えられるようになる。**計測基盤としてこれが最大の制約。**
2. **横シフトの起点は依然として自車基準**（ADR-045 未解決事項 2）。
   ADR-045 は先読みを短くして近傍の権限を稼いだだけで、起点を障害物基準に
   するのが本筋。
3. `predict_overtake_widths` の左右符号非対称（ADR-032 から継続、
   ADR-044 で最悪ケースのみ封じ済み）。
4. コーナー |kappa| 0.10-0.16 の幅中断。
5. ADR-042〜046 はいずれも本番未検証。

## 検証

`test/test_follow_state_gap_pd.py` に 6 件追加。**154 件パス**。

| ケース | 期待 |
|---|---|
| **ゲート境界の直下と直上** | **差が 0.5 m/s 未満（段差の解消・本命）** |
| 帯の中 | 横方向に対し単調増加 |
| ゲート到達 | 完全解除（`VEHICLE_V_MAX`） |
| 帯より内側 | 従来どおり車間 PD のまま |
| 帯が接触幅を挟むこと | `CLEAR - BLEND < 1.45 < CLEAR` |
| **本番ケース（横 1.86 m）** | **完全解除（ADR-043 の回帰防止）** |
| 同一レーン（帯より内側） | 先行車速を下回るまで減速 |
| `FOLLOW_LATERAL_BLEND_M` を 0 に | 従来の段差に戻る（呼び出し時に読む） |

実走（`make dev3`）は ADR-040 の基準で見る。

| 指標 | 直近 2 (073411) | 期待 |
|---|---|---|
| 試行回数 | 211 | 維持 |
| 成功件数 | 82 | 維持〜増 |
| `follow` 由来の recovery | 3 | 増えないこと |
| 抜き際の中心間 < 2.5 m | 13% | 維持〜減 |
| 目視: 抜き際の速度のばたつき | — | 減る（本命） |

**主なリスク**: 帯の中（横 1.4〜1.7 m）で従来より速度が出る。接触幅 1.45 m を
挟む帯なので物理的な接触余地は小さいが、`FOLLOW_LATERAL_CLEAR_M` 側を上げるのが
最初の調整点になる。
