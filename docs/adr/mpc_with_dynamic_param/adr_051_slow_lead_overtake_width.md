# ADR-051: 停止・低速の先行車には要求幅を下げる（中央の停止車を追い越せるようにする）

## ステータス
**撤回 (Superseded by ADR-052)**

実走で明確な退行だった。低速の相手への試行が 13 件・成功率 85% から
290 件・成功率 10%・stuck 241 件になり、recovery 全体も 23 -> 347 件に増えた。
幅は blocker ではなく、停止車には横に出るのが間に合わない
(指令 2.13m に対し実測 0.29m) のが原因で、要求幅を下げたことは
「実行できない追い越しに突入する許可」を与えただけだった。
根拠にした「低速の相手は成功率が高い」は、幅が 2.6m 以上あった
= 相手が中央から外れていた標本で、狙った母集団とは別物だった。

`MIN_OVERTAKE_WIDTH_M = 2.6` は通常速度の相手に対しては据え置き、
**停止・徐行の相手にだけ要求幅と中断閾値を下げる。**

## コンテキスト

「開始位置付近の直線でコース中央に低速／停止の車を手動配置したところ、
後続が追い越せず衝突した」という**再現条件**をいただいた。
`output/20260831-131731`（追い越し 317 件・成功 105 = 33%・recovery 23 件）で裏を取った。

### 原因: コース中央にいる車は原理的に追い越せない

コリドー幅の定義（`_compute_v2x_overtake_corridor`）:

```text
avail_left  = (ub - 0.5) - (e_y_leader + 0.8)
avail_right = (e_y_leader - 0.8) - (lb + 0.5)
```

実測のコース半幅は 3.62 m（ログの `lw + rw` から `ub - lb = 7.24`）。

| 先行車の e_y | avail_left | avail_right | max | 突入 (閾値 2.6) |
|---|---|---|---|---|
| **0.0 m（中央）** | **2.32** | **2.32** | **2.32** | **不可** |
| 0.3 m | 2.02 | 2.62 | 2.62 | 可 |
| 1.0 m | 1.32 | 3.32 | 3.32 | 可 |

**中央にいる車は左右を等分するので、どちらの側も 2.32 m にしかならず、
`MIN_OVERTAKE_WIDTH_M = 2.6` を永久に満たさない。**
車幅は 1.45 m なので物理的には余裕で通れる。
**停止車は自然とコース中央に止まるため、この状況が最も起きやすい。**

### 実測: 弾かれた 122 件の 85% は物理的に通れる

`FollowPathState` の `has_overtake_wide` が false で `follow` に落とした事象
（`no_forward_vehicle_and_no_width`）は 122 件。

```text
max(lw, rw) の分布            必要幅は 1.45m (車幅)
  0.0-1.5m:   1 件 (  1%)   通れない
  1.5-2.0m:  18 件 ( 15%)   通れる
  2.0-2.6m:  86 件 ( 70%)   通れる
  2.6m 以上: 17 件 ( 14%)
中央値 2.49m
```

### 低速の相手は最も抜きやすいのに、最も弾かれやすい

```text
先行車の速度   n    成功
 <1 km/h       3    2 ( 67%)
 1-5 km/h      7    7 (100%)
 5-10 km/h     3    2 ( 67%)
 10-20 km/h   13    3 ( 23%)
 20+ km/h    291   91 ( 31%)
```

相手が動かなければコリドーが閉じないので当然だが、
**中央に止まっている相手ほど幅が等分されて弾かれる**という逆転が起きていた。

## 決定事項

### 1. 低速の相手にだけ要求幅を下げる

```python
OVERTAKE_SLOW_LEAD_MPS = 2.8   # [m/s] これ未満を「低速」とする (10 km/h)
OVERTAKE_SLOW_WIDTH_M  = 2.0   # [m] 低速の相手に要求する最低幅


def is_slow_lead_overtake(ctx: StateContext) -> bool:
    lead = ctx.closest_forward_vehicle_speed
    return lead is not None and lead < OVERTAKE_SLOW_LEAD_MPS


def min_overtake_width(ctx: StateContext) -> float:
    return OVERTAKE_SLOW_WIDTH_M if is_slow_lead_overtake(ctx) else MIN_OVERTAKE_WIDTH_M
```

`FollowPathState` / `FollowState` の `check_transition` 冒頭で 1 回束縛し、
**突入・門番の幅の比較値だけ**を差し替える（ADR-036 / ADR-044 と同じ機械的な置換）。
条件式の構造は変えない。相手の速度が不明（`None`）なら従来どおり 2.6。

`FollowState.get_adjusted_v_max_mps` の追従車間の切り替え（`D0_M` /
`FOLLOW_TARGET_DISTANCE_M`、ADR-028）は突入判定ではないので**対象外**にした。

### 2. 中断側も揃える

`OVERTAKE_ABORT_WIDTH_M = 2.3` のままだと、2.32 m で突入した直後に
コミット期間明けで `narrow` 中断してしまい、決定 1 が無意味になる。

```python
            if side_w < OVERTAKE_HARD_ABORT_WIDTH_M:
                return self._exit(ctx, "follow", "hard_narrow")

            if (side_w < OVERTAKE_ABORT_WIDTH_M
                    and not is_slow_lead_overtake(ctx)
                    and not self._is_committed(ctx)):
                return self._exit(ctx, "follow", "narrow")
```

`narrow` は「閉じる前に降りる」ためのソフト中断なので、閉じない相手には要らない。
**物理的下限 `OVERTAKE_HARD_ABORT_WIDTH_M = 1.5` はそのまま残す。**

### 値の根拠

| 量 | 値 | 根拠 |
|---|---|---|
| 車幅 | 1.45 m | 自車半幅 0.725 × 2 |
| `OVERTAKE_HARD_ABORT_WIDTH_M` | 1.5 m | 物理的下限（既存・不変） |
| **`OVERTAKE_SLOW_WIDTH_M`** | **2.0 m** | 下限 + 0.55 m。中央の停止車（2.32 m）を通せる |
| `MIN_OVERTAKE_WIDTH_M` | 2.6 m | 通常速度の相手には従来どおり（不変） |
| **`OVERTAKE_SLOW_LEAD_MPS`** | **2.8 m/s (10 km/h)** | 10 km/h 未満の相手は成功率 67〜100%、以上は 23〜31% |

### ADR-035 決定 4（差し戻し済み）との違い

あれは**通常速度の相手**へ**コーナーで要求幅を増やす**変更で、
「突入時の幅は結果を弁別しない」ため効かず差し戻した。
本 ADR は**低速の相手**へ**要求幅を減らす**変更で、対象も方向も逆。
低速の相手では突入できさえすれば成功率 67〜100% という実測がある。

## 未解決事項

1. **通常速度（20+ km/h）の相手は成功率 31%・幅中断 47% のまま。** 今回は触らない。
   弾かれた 122 件の大半はこちら側で、`MIN_OVERTAKE_WIDTH_M` 自体を 2.2 まで下げれば
   77% を救える計算になるが、閉じるコリドーへの突入が増えて衝突が増える方向。
   低速側で効果を確認してから検討する。
2. `d_off` がコリドーの想定の半分に潰れている（ADR-050 未解決事項 1）。
3. 横シフトの起点が自車基準（ADR-045 未解決事項 2）。
4. 実測ヨーレートが指令からの期待値の 0.39 倍（ADR-049 未解決事項 2）。
5. ADR-042〜051 はいずれも本番未検証。

## 検証

`test/test_overtake_corner.py` に 9 件追加。**169 件パス。**

実値での確認（中央の停止車、左右とも 2.32 m）:

```text
先行車 停止            要求幅 2.00m -> overtake
先行車 5km/h          要求幅 2.00m -> overtake
先行車 25km/h (通常)   要求幅 2.60m -> follow      <- 従来どおり
```

| ケース | 期待 |
|---|---|
| **中央の停止車（左右とも 2.32 m）** | **突入する**（本命） |
| 同じ幅で通常速度の相手 | 従来どおり突入しない |
| 低速の相手・物理的下限未満の幅 | 突入しない |
| 相手の速度が不明 | 従来どおり 2.6 |
| 低速の相手で幅が 1.9 m に縮む | `narrow` で中断しない |
| 低速の相手で幅が 1.3 m に崩壊 | `hard_narrow` で中断する |
| 通常速度の相手で幅が 1.9 m に縮む | 従来どおり `narrow` で中断 |
| `OVERTAKE_SLOW_LEAD_MPS` の書き換え | 呼び出し時に読む |

実走はまず**再現条件**で見る（開始位置付近の直線、中央に 1 台停止 → 後続が追い越すこと）。
続いて `make dev3-rosbag` で全体を測る。

| 指標 | 20260831-131731 | 期待 |
|---|---|---|
| **中央の停止車を追い越せるか** | **不可（衝突）** | **追い越す（本命）** |
| `no_forward_vehicle_and_no_width` | 122 件 | 低速の相手の分だけ減る |
| 低速（<10 km/h）の相手への突入 | 13 件 | 増える |
| `follow_path` からの recovery | 17 件 | 減る |
| 試行回数 | 317 | 維持〜増 |
| 成功件数 | 105 (33%) | 増える |
| **通常速度（20+ km/h）の成功率** | **31%** | **不変であること**（変更漏れの確認） |

**主なリスク**: 低速の相手に 2.0 m で突入し `narrow` を飛ばすため、
相手が急に加速してコリドーが縮む場面で `hard_narrow`（1.5 m）まで粘ってしまう。
接触が増えていれば `OVERTAKE_SLOW_LEAD_MPS` を 1.4 m/s（5 km/h）へ下げるのが
最初の調整点。
