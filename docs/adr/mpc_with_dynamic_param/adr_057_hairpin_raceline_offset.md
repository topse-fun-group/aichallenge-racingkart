# ADR-057: s≈283 のヘアピンでレーシングラインを内側の縁石から離す

## ステータス
承認済み (Accepted)

`env/final_ver3/traj_mincurv.csv` の s=276-292 を、**外側（左）へ最大 0.50 m**
ずらす。**制御コードは一切変更しない。** 変更は CSV 1 ファイル・16 行のみ。

## コンテキスト

### 単独衝突が最大の損失源だった

dev / 本番の全走行で、衝突の相当数が「他車が近くに居ない」事象だった。
これらは **s=25-50 と s=275-300 の 2 か所に集中**する。

長らく原因を特定できなかった。占有格子上は衝突時に **0.75〜1.50 m** 空いており、
車体を四隅の矩形として扱っても余裕は 0.85 m あった。
速度・横位置・壁までの距離・車体四隅の余裕、**いずれも成功と失敗を分けなかった**。

### 決め手: 当たっているのは占有格子に無い「内側の縁石」だった

利用者からの情報 —「白と青の縁石」「インコース側」— で機序が確定した。
**縁石は占有格子に入っていない。** 私が測っていた 0.85〜1.50 m は
その外側にある壁までの距離で、見るべき対象を間違えていた。

裏付けとして、コーナーでの単独衝突を「自車がラインより内側にいたか」で分類した。

| s | kappa | 内側 | 自車 e_y | 内側寄りか |
|---|---|---|---|---|
| 159 | +0.085 | 左 | **+0.28** | はい |
| 282 | −0.217 | 右 | **−0.61** | はい |
| 283 | −0.207 | 右 | **−1.08** | はい |
| 283 | −0.207 | 右 | −1.05 | はい |
| 283 | −0.207 | 右 | −0.71 | はい |
| 283 | −0.207 | 右 | −0.70 | はい |
| 284 | −0.139 | 右 | −0.63 | はい |
| 316 | −0.106 | 右 | −0.17 | はい |

**8 / 8 件 (100%) で自車がラインより内側**にいた。内側へ中央 0.67 m。

これで過去の観測がすべて説明できる。

- **「速い方が安全」だった逆説** — 33 km/h では外へ膨らんで `e_y` −0.17〜−0.30、
  24.7 km/h では素直に走って −0.55〜−1.08。**縁石は内側にあるので膨らむ方が安全**。
  s=280-285 の通過 31 回で 28〜33 km/h は 0/11、24.7 km/h は 6/15 が失敗した。
- **壁までの余裕が成否を分けなかった理由** — 測っていたのが縁石ではなく壁だった。
- **`traj_mincurv` は最小曲率ラインなので構造的にインを舐める。**
  ライン自体が縁石すれすれを通っている。

## 決定事項

### s=276-292 を外側へ最大 0.50 m ずらす

```text
変位 w(s) = 0.50 * 0.5 * (1 - cos(2*pi*(s-276)/16))     [m]、左（外側）が正
新しい座標 = (x - sin(theta)*w, y + cos(theta)*w)
```

レイズドコサインなので**両端で変位も 1 階微分も 0** になり、窓の外は完全に不変。

| s | 変位 | 内側(右)の余地 旧 → 新 | 外側(左) 旧 → 新 |
|---|---|---|---|
| 281 | 0.32 | 2.80 → **3.00** | 4.80 → 4.65 |
| 282 | 0.41 | 2.50 → **2.90** | 4.20 → 3.85 |
| 283 | 0.47 | 2.30 → **2.85** | 3.95 → 3.45 |
| **284** | **0.50** | 2.25 → **2.75** | 3.85 → 3.35 |
| 286 | 0.44 | 2.30 → **2.75** | 4.30 → 3.85 |
| 288 | 0.28 | 2.25 → **2.60** | 4.20 → 3.95 |

**衝突が集中する s=282-284 で内側に +0.40〜+0.55 m** 稼ぐ。外側は 3.35 m 以上残る。

### 窓を s=276 より手前に広げてはいけない

s=270-276 は**逆向きの左コーナー**で、内側（左）の余地が 2.05〜2.25 m しかない。
ここへ左シフトを伸ばすと、今度は左の縁石に当たる。窓の下端は 276 が上限。

### なぜ CSV か（制御コードではなく）

`load_ref_path` が読むのは **`x_m` と `y_m` だけ**
（`psi_rad` / `kappa_radpm` は返り値を捨てており、座標から再計算される。
`vx_mps` を読む `load_ref_path_speed_profile` は**呼び出しが無い**）。
コース幅 `ub` / `lb` も新しい waypoint から自動で再レイキャストされる。

したがって **`x_m` / `y_m` の 16 行だけを書き換えれば足りる**。
派生列（`s_m` / `psi_rad` / `kappa_radpm`）は使われないので触っていない。
**駄目なら CSV を git で戻すだけで完全に元に戻る。**

利用者からは当初「`FollowPathState` のときだけ」という案をいただいたが、
コーナーでの単独衝突は `follow_path` だけでなく `overtake` でも起きているため、
ライン自体を直す方が対象を漏らさない。制御コードに触れない利点も大きい。

## 未解決事項

1. **残る 3 件（s=159 の左コーナー、s=316）は未対応。** 内側寄りの度合いが
   +0.28 / −0.17 と小さく、同じ 0.50 m では過剰の恐れがある。
   **本 ADR の効果を確認してから**個別に検討する。
2. **s=25-50 の集中も未対応。** ここは他車が 2.5〜3.4 m に居る事象が多く、
   単独か接触かの切り分けができていない。
3. **なぜ低速時に 0.6〜1.1 m も内側へ入るのかは未解明。** Pure Pursuit の
   コーナーカットなら先読み距離が短い低速ほど小さいはずで、逆になっている。
   本 ADR は「内側へ入っても当たらない位置にラインを置く」対症であり、根治ではない。
4. 縁石の実際の位置は不明。占有格子に無いため、必要な余裕は実走でしか測れない。

## 検証

**164 件パス**（ユニットテストはラインに依存しないため不変）。

書き込み後の数値確認。

```text

座標の変位  最大 0.499 m / 非ゼロ 16 点 / 窓外 0.000000 m

```

実走は **`make dev3-rosbag` の 40 周 A/B**。基準は `naito_v1.3.6a`
（`output/20260831-210615`）。

| 指標 | 基準 | 期待 |
|---|---|---|
| **s=275-300 の単独衝突** | **7 件 / 334 周** | **減る（本命）** |
| 衝突 /周 | 0.296 | 減る |
| recovery /周 | 0.082 | 減る |
| 成功 /周 | 1.152 | **維持**（ラインが変わるので要確認） |
| ラップ 中央 | 48.7 s | **維持**（伸びていないこと） |
| **s=270-278 での新規衝突** | **0 件** | **0 のまま**（左の縁石に当たっていないこと） |

**主なリスク**: 外側へずらしたことで s=270-276 の左コーナーからの進入線が変わり、
左側で新たに当たる可能性。窓を 276 から始めて左コーナー側の余地
（2.05〜2.25 m）を削らないようにしたが、実走で s=270-280 の衝突が出ていないかを見る。
出ていれば `AMP` を 0.5 → 0.3 に下げるか、窓を s=278-292 に狭めるのが調整点。
