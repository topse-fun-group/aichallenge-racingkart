# ADR-034: 将来幅の予測を経路相対にする（位置外挿の撤回）

## ステータス
承認済み (Accepted) — **ADR-032 の決定 1（予測位置での関数再呼び出し）を supersede する**

## コンテキスト

ADR-032/033 適用後も、回頭角 120° 以下のコーナーで幅の無いインへ寄せて衝突・停止する
現象が**毎回同じコーナーで**残った。`output/20260830-061852`（追い越し 50 件）で裏を取った。

```text
出口: hard_narrow 18 / passed 12 / narrow 11 / lost 6 / stuck 3
突入時に side_w < 2.6m: 30%   < 1.5m: 22%
```

| \|kappa\| | 内側 | 外側 |
|---|---|---|
| 0.05–0.10 | n=4 **成功 0%** | n=0 |
| 0.10–0.16 | n=12 **成功 0%** | n=1 |
| 0.16–0.30 | n=15 成功 20% | n=11 成功 55% |

**中曲率帯で内側が 12:1 で選ばれ、成功率 0%。**

### 原因: 位置外挿がコーナーで「内側が広い」と誤認させていた

ADR-032 の決定 1 は `V2XVehicleTracker.predict_positions()`
（**等速直線・グローバル座標**）で先行車の T 秒後の位置を作り、
そこで `_compute_v2x_overtake_corridor` を呼ぶものだった。
コーナーでは直線外挿が接線方向へ飛ぶため、予測点が**外側に大きくずれる**。

```text
    R[m]  v[km/h]  走行距離[m]  外側へのずれ[m]
     4.1      25       6.94          3.96
     6.0      25       6.94          3.18
     8.9      25       6.94          2.39
```

```text
        予測点 (接線方向へ外挿)  ×  <- 外側の壁の付近／外
                            ／
      ●先行車 ────────────
   ~~~~~~~~~~ traj_mincurv (コーナーではインにつく)
   ─────────────
```

コース半幅は約 3 m なので予測点は外側の壁付近〜壁の外に出る。すると

```text
avail_outside = (ub - 0.5) - (e_y_leader + 0.8)  ->  ほぼ 0
avail_inside  = (e_y_leader - 0.8) - (lb + 0.5)  ->  大きい
```

となり、**コーナーのたびに「内側が広い」と誤認して内側を選ぶ**。実測の 12:1 と一致する。
決定 1 の狙いだった「コーナーで `ub`/`lb` 自体が変わる効果を拾う」は、
外挿誤差がその効果を桁で上回るため成立していなかった。

### もう一つの前提バグ: `heading_diff` の基準フレーム

`forward_vehicle_heading_diff` は
**「先行車の速度方位 − *自車の*最近傍 waypoint の psi」**で計算されていた。
車間 4 m・R=6.7 m のコーナーでは経路自体が 34° 回るため、先行車が完璧にラインに
乗っていても 34° と出る。`sin(34°) = 0.56` なので横移動量が約 5 m と算出され、
**コーナーのたびに左右判定が反転する**。ADR-032 の未解決事項 2。

## 決定事項

### 1. 将来幅は経路相対で求める

先行車の速度をセンターラインの**法線方向**に分解し、横加速度 A で T 秒進んだ
移動量 d を左右の幅に加減する。経路フレームから出ないので外挿の破綻が無い。

```text
sin_hd = sin(heading_diff)
d      = lead_speed * sin_hd * T  +  0.5 * A * T^2 * sign(sin_hd)
left_future  = max(0, overtake_width_left  - d)
right_future = max(0, overtake_width_right + d)
```

先行車が左へ寄る（`heading_diff > 0`）なら左が狭まり右が広がる。

**向きは `heading_diff` の符号で決める。** `v_lat` の符号から取ると、先行車が
停止しているときに加速度項まで消えてしまう。

| 定数 | 意味 |
|---|---|
| `OVERTAKE_PREDICT_HORIZON_SEC` | 予測ホライズン T |
| `OVERTAKE_PREDICT_LAT_ACCEL_MPSS` | 先行車の横方向加速度の見積り A = 2.5 |

実装は `states.predict_overtake_widths()`（純関数）。rclpy 無しで単体テストできる。

### 2. `heading_diff` を先行車の waypoint 基準にする

`_compute_v2x_overtake_corridor` は先行車の最近傍 waypoint の `psi` を
**既に内部で計算している**ので、4 番目の戻り値として返して使う。

```python
fwd_heading_diff = wrap(fwd_heading - leader_psi)   # 旧: path_psi (自車基準)
```

**既存の `has_future_width` もこの値を使うため挙動が変わる**（曲率由来の汚染が消える方向）。
条件式そのものは触っていない。

### 3. 位置外挿とその付帯コードを削除

`predict_positions` 呼び出しに加え、それに渡すためだけに `_detect_forward_and_side_vehicles`
へ足していた `target_corridor_vid` / `best_vid` / `side_vehicle_vid` も削除し、
元のシグネチャに戻した。差し引きで行数は増えていない。

## 追記: 適用範囲をコーナーに限定し、寄せ側を固定する

決定 1〜3 を全区間に適用したところ、**直線で追い越し幅も速度差も十分なのに追い越さず、
幅寄せとセンターライン寄せを繰り返す**挙動が出た。
`output/20260830-065504`（追い越し 68 件）で裏を取った。

```text
出口: hard_narrow 24 / narrow 19 / lost 11 / passed 11 (16%) / stuck 3

|kappa| 別        n   passed
  0.00-0.05 直線  11    1 (9%)   <- 直線でもほぼ失敗。hard_narrow 5
  0.10-0.16 中    24    4 (17%)
  0.16-0.40 急    31    6 (19%)
```

### 直線で失敗していた機序（3 つの重なり）

**1. 加速度項がコース幅を超えて飽和していた。**
`T=2.0` / `A=2.5` で `0.5·A·T² = 5.00 m`。コース半幅は約 3 m なので、
`heading_diff` がわずかでも非ゼロなら片側の将来幅は必ず 0 に飽和する。
結果として `resolve_overtake_side` は**実質 `sign(heading_diff)` だけ**で決まっていた。

**2. その `heading_diff` が極めてノイジー。**
V2X は 20 Hz の 2 点差分・無平滑。位置ノイズ σ=0.1 m から速度ノイズ σ = 2.8 m/s。

```text
先行車 18km/h -> 方位ノイズ σ = 30deg   sin の振れ ±0.49
先行車 25km/h -> 方位ノイズ σ = 22deg   sin の振れ ±0.37
先行車 35km/h -> 方位ノイズ σ = 16deg   sin の振れ ±0.28
```

1 と合わせて**寄せ側が毎 tick 反転しうる**状態だった。

**3. 操舵と中断判定が別々の側を見ていた。**
`OvertakeState.on_enter` が `_overtake_side` をラッチする一方、
`_compute_waypoint_shift_pure_pursuit_control` は毎 tick `resolve_overtake_side(ctx)` を
呼び直していた。

```text
操舵      -> ライブ側 (毎 tick 反転しうる)
中断判定  -> ラッチ側 (突入時に固定)
```

ライブ側が反転すると「幅寄せ ↔ 反対側／センターライン」を繰り返し、
その間にラッチ側の幅が崩れて `hard_narrow` になっていた。

### 追加の決定

**4. 予測は `in_tight_corner`（回頭角 120° 未満）のときだけ掛ける。**
直線では `将来幅 = 現在幅` とする。これで `resolve_overtake_side` の
`min(now, future)` が `min(now, now)` に退化し、
**ADR-032 以前の「現在幅が広い側」という安定・決定的な判定に戻る**。
直線には予測すべき曲率由来の幅変化が無く、ノイズだけが入るため。

**5. 追い越し中の操舵は突入時にラッチした側に固定する。**
既にデッドコードになっていた `shift_side` 引数
（`FollowState.control_mode` が `PURE_PURSUIT` になったため常に `None`）を再利用し、
`OvertakeState._overtake_side` を渡す。操舵と中断判定が同じ側を見るようになる。

**6. `OVERTAKE_PREDICT_LAT_ACCEL_MPSS` を 2.5 → 0.6。**
`T=2.0` で `0.5·A·T² = 1.20 m`。先行車 25 km/h・`hd=10°` の速度成分 2.43 m と
同オーダーになり、片側が 0 に張り付かなくなる。

## 未解決事項

1. `ctx.forward_vehicle_gap` が常に 0.0 で `is_ttc_close` が全経路恒真（最優先）
2. `has_future_width` の左右符号非対称（`abs()` で符号を捨て、左に `−`・右に `+` を固定適用）
3. `OVERTAKE_CORNER_KAPPA = 0.05` を実行時 waypoint の 66% が超え、`is_corner` が事実上常に True
4. ヘアピン 5 区間（回頭角 149〜184°）に速度上限が掛からない（ADR-033 決定 2 の指定どおり）
5. **V2X の速度は 2 点差分・無平滑**（dt=0.05 s、位置ノイズ σ=0.1 m なら速度 σ≈2.8 m/s）。
   `sin(heading_diff)` はこの速度方位から作るため、予測の精度はここに律速される。
   先行車 25 km/h で方位ノイズ σ≈22° (訂正: 実測は中央 1.3〜2.0°、ADR-042) は、コーナー限定にしてもなお大きい。
   **本質的な改善には速度推定の平滑化（移動平均かローパス）が要る。**
   `V2XVehicleTracker` のバッファは `maxlen=2` なので、まず窓を伸ばす必要がある。
6. **加速度項が支配的になりうる。** `0.5 * A * T^2` は T=1.0 で 1.25 m、T=2.0 で **5.0 m**。
   コース幅を超えると片側が必ず 0 に張り付き、側の選択が実質 `sign(heading_diff)` だけで
   決まる。T を伸ばす場合は A の再検討が要る。

## 検証

- ユニットテスト 97 件（`predict_overtake_widths` に 8 件追加）
  - 左右へ寄るときの符号／平行なら現在幅と一致／停止中でも加速度項が残る
  - 幅が負にならない／指定の式と一致する数値／側の選択が反転すること
  - 定数がモジュールグローバルから呼び出し時に読まれること
- 実走: `output/20260830-061852` と同じ集計で比較。特に
  **|kappa| 0.05–0.16 帯の内外比（今回 内 16 : 外 1）**と同帯の成功率（今回 0%）、
  `hard_narrow` の件数（今回 18）、突入時 side_w < 1.5m の割合（今回 22%）。
