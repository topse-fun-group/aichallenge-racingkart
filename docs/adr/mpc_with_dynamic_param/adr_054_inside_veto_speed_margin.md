# ADR-054: コーナー内側の veto を「自車より十分に遅い相手」には掛けない

## ステータス
承認済み (Accepted) — **本番で検証済み (2026-09-01)**

競争環境で勝った `naito_v1.3.6a`（`1788188497162`）で、
**内側への突入が 0 件 -> 7 件、うち 5 件成功 (71%)**。
突入時の速度余裕は 11.4〜26.0 m/s で閾値 3.0 に対し十分だった。
12km/h 未満 18%・recovery 1 件・衝突 3 件・壁越え 0.0s といずれも 4 走行中の最良。
ADR-036 の「内側は成功 7%」が 24km/h の相手に限った話だったことが確かめられた。
残った課題（突入直後の接触）は ADR-056 へ引き継ぐ。

`is_inside_corner_overtake` の停止車例外（ADR-039）を、
**「その地点で出せる速度が先行車速を 3.0 m/s 以上上回るとき」** へ広げる。
**幅の門番と中断条件は一切変更しない。**

## コンテキスト

競争環境の `naito_v1.3.6` 3 走行（`1788135353082` / `1788164700847` /
`1788170410717`、各 6 周・349〜368 s）を rosbag + ログで解析した。

> 併せて共有された `c7d1e6ed-8266-...` は `[MPPI]` / `[BOOST]` を出す
> `multi_purpose_mpc_ros`（別パッケージ）の走行で、`_with_dynamic_param`
> ではないため解析から除外した。

### 損失の所在

最良ラップ **39.0 s** に対し実際は 349〜368 s / 6 周。42 s/周なら 252 s なので
**1 レースあたり約 100 s を失っている。** 損失は薄く広がっておらず、
**77〜87 s の「壊れたラップ」2〜3 本**に集中する。

| 走行 | ラップ [s] | 12km/h 未満 | 追い抜かれ / 追い抜き |
|---|---|---|---|
| 135353082 | 86.9 / 48.5 / 48.7 / 48.8 / 77.3 / 49.4 | 69 s (19%) | 3 / 9 |
| 164700847 | 85.3 / 76.5 / 49.4 / 50.2 / 55.5 / 48.7 | 85 s (23%) | 2 / 11 |
| 170410717 | 54.6 / 78.9 / 39.0 / 55.6 / 77.6 / 41.3 | 95 s (27%) | 2 / 5 |

「前方 10 m 以内に他車がいて双方 15 km/h 未満」の時間は 3 走行合計
**244 s（レースの 22%）**。自車速 中央 4.6〜6.8 km/h に対し先行車は
9.6〜10.0 km/h で、**自車の方が遅い**。位置は **s=250-350 に 113 s、
s=0-50 に 66 s**（計 179/244 s）で、報告された「開始位置手前の最後のコーナー」に一致する。

### 撤回した仮説（記録として残す）

最初は「突入の速度ゲート `speed_diff = v_ego - lead >= 2.0` が低速追従中
92% 不成立」を主因と見て実装したが、**誤りだったので撤回した。**

`FollowState` の 4 枝のうち `safe_width` だけ速度ゲートを持たず、
低速の相手に対しては **`safe_width` の方が常に緩い**
（`is_slow_leader` は lead ≤ 25 km/h で成立し、`is_ttc_close` は
`forward_vehicle_gap` が常に 0 のため恒真）。
速度ゲートを緩めても新たに開く場面が無い。ユニットテストを書いた時点で
`safe_width` が発火して判明した。**「成立率が低い条件」と
「実際に止めている条件」を取り違えていた。**

### 測り直し: 実際に足止めされている 132 s の内訳

244 s のうち **85 s (35%) は既に `overtake` に入っていた**（低速のまま試行中）。
突入できずにいるのは `follow` の **132 s**。そこに限って門番を再現すると
順位が入れ替わる。

```text
follow 状態での低速追従 132s (3 走行)
  ★ is_inside_corner で veto      39%   <- 最大。うち 31 ポイントは幅が足りている
    幅 2.6 未満で不成立             36%
    側方車あり                     41%
    safe_width が通るはず           15%  (20s)

  幅の閾値を下げた場合の通過率: 2.6 -> 15%  2.5 -> 19%  2.3 -> 27%
```

幅は 2.5 に下げても 4 ポイントしか動かず、ADR-052 の
「幅は blocker ではない」と整合する。**最大の門番は内側 veto。**

### veto の根拠は別の母集団で測られていた

ADR-036 の根拠は「内側 46 件 成功 7% / 幅で中断 76%」だが、これは
`20260830-221428`（**全車が自コードで約 24 km/h**）の実測だった。
veto の論拠は「コーナーが進むにつれて先行車の動きとコース形状で内側が閉じる」で、
**自車の 1/3 の速度しか出していない相手には前提が当てはまらない。**

### 閾値は 2 つの母集団が分離する位置に置いた

コーナー（`|kappa| > OVERTAKE_CORNER_KAPPA`）での
「出せる速度 − 先行車速」（`cap = min(35km/h, sqrt(ay_max/|kappa|))`,
`ay_max` は `FollowState.AY_MAX = 6.5`）の実測。

| 母集団 | n | 5% | 25% | 中央 | 75% | 95% |
|---|---|---|---|---|---|---|
| **ADR-036 の母集団**（先行車 20-30 km/h） | 11665 | -1.57 | -1.01 | **-0.15** | 0.14 | **1.05** |
| **低速 NPC**（先行車 5-15 km/h） | 332 | **2.26** | 3.08 | **3.54** | 4.29 | 5.80 |
| 停止車（<1.8 km/h、ADR-039 の対象） | 22 | 5.46 | 5.60 | 5.63 | 5.82 | 8.15 |

| 閾値 | ADR-036 の母集団が例外へ漏れる | 低速 NPC を拾える |
|---|---|---|
| 2.0 m/s | 1% | 99% |
| **3.0 m/s（採用）** | **0%** | **80%** |
| 4.0 m/s | 0% | 33% |

**3.0 m/s を採る。** veto の根拠データへの漏れが 0% で、狙った母集団は 8 割拾える。

## 決定事項

### 内側 veto の例外に速度余裕を追加する

```python
OVERTAKE_INSIDE_VETO_MARGIN_MPS  = 3.0   # [m/s]

# is_inside_corner_overtake、ADR-039 の停止車例外の直後
    if lead is not None and (
            ctx.speed_cap_mps - lead) >= OVERTAKE_INSIDE_VETO_MARGIN_MPS:
        return False
```

`ctx.speed_cap_mps` は `StateContext` に新設し、`_build_state_context` で
`_control` のコーナー速度上限（ADR-033 決定 2）と同じ式で与える。
`ay_max` は状態遷移時に `get_params()` で書き換わるため、状態ごとの実力を反映する。
`STATE_PARAM_MAP` に `overtake_inside_veto_margin_mps` を追加。

**変更は突入の側の判定だけ。** 幅の門番（`MIN_OVERTAKE_WIDTH_M` /
`OVERTAKE_ABORT_WIDTH_M` / `OVERTAKE_HARD_ABORT_WIDTH_M`）と
`narrow` / `hard_narrow` の中断は**一切触っていない**。
ADR-051 の失敗は幅と中断を同時に緩めたことだった。

## 限界（重要）

**10 km/h の相手に内側で仕掛けた実績は 1 件も無い。** veto が常に塞いできたため。

`先行車 <10 km/h × 内側` は 9 件・成功 8（89%）あるが、
**全件 1.8 km/h 未満**で ADR-039 の停止車例外から入ったものであり、
10 km/h の母集団の証拠ではない。

```text
内側 × 先行車 <10km/h の 9 件（本番 3 本 + dev 2 本）
  先行車速 0.00-1.77 km/h、すべて ADR-039 の例外経由、passed 8 / hard_narrow 1
```

ADR-052 で犯した「緩めた先の母集団を、緩める前の母集団の成功率から外挿する」
誤りを繰り返さないため、**これは実験であって確定した改善ではない**と明記する。
根拠は 4 点に限られる。

1. 止めている量が最大（`follow` 132 s の 39%、うち 31 ポイントは幅が足りている）
2. veto の根拠（ADR-036）が別母集団で測られている
3. 物理的な論拠（自車の 1/3 の速度の相手はコーナーをゆっくり消費する）
4. ADR-039 の先例（停止車では 8/9 成功）

## dev A/B の結果（2026-08-31、本 ADR 投入後）

`make dev3-rosbag` の 40 周 A/B。A = `naito_v1.3.6`（`output/20260831-163410`）、
B = v1.3.6 + ADR-049 + ADR-054（`output/20260831-210615`）。
収録 1979 / 1984 s、3 台合計 121.4 / 121.6 周。

| 指標 | A: v1.3.6 | B: +049+054 |
|---|---|---|
| 追い越し 試行 | 393 | 393 |
| 成功 | 144 (37%) | 140 (36%) |
| 幅で中断 | 48% | 45% |
| recovery（うち `overtake` 由来） | 11 (5) | 10 (2) |
| 衝突（うち他車由来） | 34 (29) | 36 (29) |
| 12 km/h 未満 | 402 s (7%) | 441 s (7%) |
| ラップ 中央 / 最良 | 48.7 / 38.9 | 48.7 / 38.9 |
| **壁境界を越えた時間** | **24.5 s** | **6.7 s** |

| 自由走行 \|e_y\| 中央 / 95% / 最大 | 0.330 / 0.88 / 3.29 | 0.330 / 0.82 / 2.77 |

**退行なし。** 壁際は B が良いが、A の壁越え 24.5 s のうち 20.9 s は d2 一台の
外れ値（A の d2 は衝突 22 件、B の d2 は壁越え 1.1 s）で、一走行ずつでは断定できない。

### dev はこの ADR を検証できない

**内側への突入は A 0 件 → B 4 件（成功 1）しか発生しなかった。** 交通が違う。

| ログ上の先行車速 | n | <5 km/h | 5-15 | 15-22 | 22+ | 中央 |
|---|---|---|---|---|---|---|
| **本番 3 走行** | 817 | 4% | **46%** | 6% | 43% | **14.7** |
| dev A | 7476 | 1% | **0%** | 0% | 99% | 24.8 |
| dev B | 7386 | 1% | **1%** | 0% | 98% | 24.8 |

本 ADR が狙う 5-15 km/h の相手は本番の 46% だが dev には 0〜1% しか居ない。
`make dev3` は自コード 3 台が同じ速度で走るため構造的に再現できない。

**低速車の再現は見送った。** 既存の ROS パラメータでは実現できず
（`vehicle_v_max` は `FollowState.get_adjusted_v_max_mps` でしか使われない、
`v_max` は状態遷移のたび `mpc_controller.py:1325` で上書きされる）、
`_control` の速度指令経路に手を入れる必要があるため。

**したがって本 ADR の判定は次の競争環境の走行で行う。**
そのために `_exit` ログへ `cap=`（その地点で出せる速度 [km/h]）を追加した。
`cap - forward_v >= OVERTAKE_INSIDE_VETO_MARGIN_MPS` の成立率を事後に数えられる。
挙動は不変。


## 追記: 本番データでの効果見積もり（2026-09-01）

本番 3 走行で `follow` に足止めされている 132 s を、競争環境の実交通
（d2 = プレイヤー 22〜25 km/h、d3 = NPC 中央 6 km/h）で再解析した。

```text
足止めの相手:  d3 (NPC) 81%   d2 (他プレイヤー) 19%

  内側 veto           現状 38%  ->  本 ADR 後  2%    （37s を解放）
  幅 2.6 未満            36%   （本 ADR では変わらない）
  ★ 突入できる状態     現状 33%  ->  本 ADR 後 61%
```

**足止めの 8 割は低速 NPC が相手で、最大の門番だった内側 veto をほぼ外せる。**
NPC は中央 6 km/h なので、直線でもコーナーでも
`speed_cap - lead >= OVERTAKE_INSIDE_VETO_MARGIN_MPS (3.0)` がほぼ常に成立する。

**残る最大のブロッカーは幅の門番（36%）になる。** 道幅中央 7.08 m では
中央にいる相手に対し `max(lw, rw)` は 2.24 m にしかならず、
閾値 2.6 を満たすのはコースの 8%（2.5 で 15%、2.3 で 57%）。
ADR-052 で 2.0 への引き下げを撤回しているため、
**本 ADR の本番結果を見てから**改めて検討する。
相手が停止車ではなく 6 km/h で動いている点が ADR-052 の母集団とは違う。


## 未解決事項

1. **ペナルティ 52 s（レースの 3〜8%）。** 速度がちょうど 5.0 km/h に張り付く区間が
   3 走行で 17 回。指令 20〜35 km/h・指令加速 +3.0 m/s² に対し実速度 5.0 km/h 一定で、
   外部クランプとしか説明がつかない。`docs/interface/evaluation-interface.md` の
   `penalty_by_kind`（`crash` / `wall` / `over`）に対応するとみられる。
   **衝突削減の価値が従来の想定より大きい。**
2. **側方車の判定が `follow` 足止めの 41% で立っている。** 2 番目に大きい門番だが、
   検知コーン（30-150°、0-3 m）の妥当性を確認していない。
3. 幅の閾値（2.6 → 2.5）は 15% → 19% の 4 ポイントで、単独では効果が小さい。
4. 横シフトの起点が自車基準（ADR-045 未解決事項 2）。
5. ADR-049 / 054 とも本番未検証。

## 検証

**164 件パス**（ADR-054 分 10 件を追加、既存 2 件を更新）。

既存 2 件（`test_follow_path_state_also_skips_the_inside` /
`test_a_leader_above_the_moving_threshold_is_still_vetoed`）は
低速の先行車を使っていたため新しい例外が正しく発火した。
元の検証意図を保つため、`speed_cap` を「先行車 +2.0 m/s」にして
余裕側を潰した文脈へ更新した。

| ケース | 期待 |
|---|---|
| **先行車 10 km/h・出せる速度 25 km/h・内側が広い** | **veto しない**（本命） |
| **先行車 24 km/h・出せる速度 28 km/h**（ADR-036 の母集団） | **従来どおり veto**（最重要の回帰防止） |
| ヘアピン（出せる速度が先行車 +1.0 m/s） | 従来どおり veto |
| 余裕がちょうど 3.0 / 3.0 の直下 | 例外 / veto |
| 停止車（ADR-039） | 従来どおり例外 |
| 外側・直線 | 影響なし |
| `OVERTAKE_INSIDE_VETO_MARGIN_MPS` の書き換え | 呼び出し時に読む |
| `StateContext.speed_cap_mps` の既定値 | `VEHICLE_V_MAX / 3.6` |

実走は **40 周 A/B**（ADR-053 の基準）。ADR-049 も同時に入るので
**A = `naito_v1.3.6`、B = v1.3.6 + ADR-049 + ADR-054** の比較になる。
評価順は ADR-040（成功件数 → 試行回数 → 低速時間 → 成功率）。

| 指標 | A: v1.3.6 の実測 | 期待 |
|---|---|---|
| **`follow` での低速足止め** | **132 s / 3 走行** | **減る（本命）** |
| **内側 veto での不成立** | **39%** | **大きく減る** |
| 追い越し試行 | 12 / 18 / 29 件 | 増える |
| **成功件数** | **9 / 7 / 11 件** | **増える** |
| 12 km/h 未満 | 19 / 23 / 27% | 減る |
| ラップ中央 | 49.1 / 52.8 / 55.1 s | 短縮 |
| **`narrow` + `hard_narrow` の割合** | 内側は従来 0 件 | **増えていないこと**（最重要の退行指標） |
| 5 km/h ペナルティ | 17 回 / 52 s | 増えていないこと |
| recovery | 3 / 4 / 2 件 | 増えていないこと |

**主なリスク**: 参照経路が最小曲率ラインで既にインを舐めているため、
内側には構造的に幅が無い。10 km/h の相手でも同じなら
`hard_narrow` と `overtake` 由来の recovery が増える。
**中断条件を一切触っていない**ので、失敗しても「入って中断する」で収まり、
ADR-051 のような「実行できない追い越しに突入し続ける」状態にはならないと判断する。
退行していれば `OVERTAKE_INSIDE_VETO_MARGIN_MPS` を 3.0 → 4.5 へ上げるのが
最初の調整点（低速 NPC の 21% だけに絞られる）。
良好なら 2.0 へ下げて 99% を拾う。
