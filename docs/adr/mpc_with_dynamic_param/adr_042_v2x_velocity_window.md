# ADR-042: V2X 速度推定を 0.25s 窓の差分にする（隣接 2 点差分の廃止）

## ステータス
承認済み (Accepted)

`V2XVehicleTracker` の速度推定を隣接 2 サンプル差分から時間窓差分に変える。
**ADR-027 以降ずっと未解決事項に挙げていた「V2X 速度が 2 点差分・無平滑」の解消。**

## コンテキスト

`naito_v1.3.5` の本番走行で敗北。ログに加えて **rosbag（mcap）が初めて入手できた**ので、
状態遷移ログではなく実データで解析した。

### v1.3.4 からは大きく改善している

```text
周回     49.1 / 77.9 / 39.1 / 43.1 / 51.8 / 79.7 s   合計 340.8s
(v1.3.4)  run A 431.3s / run B 434.0s
recovery  2 件 (v1.3.4: 3 件 / 11 件)     デッドロック消滅 (ADR-039)
追い越し  42 試行 15 成功 (36%)           直線 7 試行 6 成功 (86%)
```

ADR-039〜041 は効いている。残る問題は**コーナーの追い越し精度**。

```text
コーナー  35 試行  9 成功 (26%)  幅で中断 22 (63%)
  |kappa| 0.10-0.16  n=15  成功 3 (20%)  幅中断 12 (80%)   <- 最悪
  |kappa| 0.16-0.25  n=16  成功 5 (31%)  幅中断  7 (44%)
```

### 時間ロスの実測（odometry）

```text
低速 (<12km/h が 0.5s 以上) のエピソード 12 件  合計 76.3s = 走行 352s の 22%

長い順   13.0s (最低 5.0km/h)   12.1s (2.4km/h)   10.3s (recovery)
         9.1s (recovery)        7.1s (スタート)    6.6s (0.6km/h)
```

上位 2 件（13.0s / 12.1s）は recovery ではなく、**遅い車の後ろで時速 5km/h で
這っている**時間。V2X の実位置で確認すると、相手（d3）との距離は 1.6〜9.8 m。

### 根本原因: V2X 速度推定が使い物になっていない

`V2XVehicleTracker` は `deque(maxlen=2)` で**隣接 2 サンプルの差分**を取る。
V2X は 20Hz（実測のサンプル間隔は中央 0.07s）なので、位置ノイズがそのまま
速度に乗る。本番 rosbag をトラッカ本体に通した実測:

```text
                 中央値      最大推定     tick間ジッタ 中央 / 95%
d2  従来        23.0km/h   63.6km/h        9.04 / 22.53 km/h
d2  0.25s 窓    24.8km/h   44.7km/h        0.86 /  6.55 km/h
d3  従来         7.3km/h   28.8km/h        2.76 /  8.86 km/h
d3  0.25s 窓     7.7km/h   18.2km/h        0.42 /  2.48 km/h
```

**実車は 35km/h 以下なのに最大 63.6km/h と推定し、tick ごとに 9km/h 振れていた。**

これで、これまで説明できなかったことが一斉に説明できる。

- `speed_diff` による層別が弁別しない（相対速度が ±10km/h のノイズだった）
- `is_slow_leader`（絶対 25km/h 以下）が、25km/h 付近の相手ではコイン投げになる
  （d2 の真値 24.8km/h に対し従来推定の中央値 23.0km/h、最大 63.6km/h）
- `passed` した突入の相対速度中央値が **−1.05km/h**（自車が遅いのに抜けている）
- `has_future_width` / `predict_overtake_widths` が機能しない

**リーダー速度を使う判断はすべてノイズの上で行われていた。**

### 訂正: 方位ノイズは σ≈22° ではなかった

ADR-034 以降「V2X 速度 σ≈2.8m/s → heading σ≈22°」と書き、将来幅予測が
効かない理由として繰り返し引用してきたが、**これは推定であり誤りだった。**
実測の tick 間方位ジッタは中央 1.27〜2.03°、95%tile で 4.4〜5.6°。

したがって将来幅予測が効かない理由は方位ノイズではない。別の原因を探す必要がある
（未解決事項 1）。

## 決定事項

### 速度差分を時間窓にする

`v2x_vehicle_tracker.py`。

```python
V2X_VELOCITY_WINDOW_SEC = 0.25
_SAMPLE_MAXLEN = 16          # 0.25s / 0.07s の余裕

# update() 内
t1, x1, y1 = buf[-1]
t0, x0, y0 = buf[-2]                    # 既定は直前サンプル (従来と同じ)
for sample in list(buf)[:-1]:           # 最新自身を選ぶと dt=0 になるので除く
    if t1 - sample[0] <= self._window:
        t0, x0, y0 = sample
        break
dt = t1 - t0
```

窓より粗くしか届いていないとき（起動直後・欠測時）は直前サンプルに落ちるので、
**従来と同じ挙動**になる。ジャンプ検出と `v_max_safety` クランプは変更なし。

`velocity_window_sec` はコンストラクタ引数（既定 0.25）にしてあるので、
config を触らずに済み、必要なら注入で変えられる。

### 窓長 0.25s の根拠

本番 rosbag での実測。窓を延ばすほどジッタは減るが遅れが増える。

| 窓[s] | ジッタ中央 | ジッタ95% | 最大推定 | 遅れ |
|---|---|---|---|---|
| 0.00（従来） | 4.57 | 19.70 | 63.6 km/h | 0 |
| 0.15 | 0.80 | 5.81 | 44.7 | 0.075 |
| **0.25** | **0.62** | **4.70** | **43.9** | **0.125** |
| 0.35 | 0.37 | 3.19 | 41.7 | 0.175 |
| 0.50 | 0.30 | 2.27 | 41.4 | 0.250 |

0.25s は遅れ 0.125s。制御周期 0.025s、コミット期間 1.5s、予測ホライズン 2.0s の
いずれに対しても十分小さい。0.5s まで延ばしてもジッタの改善は半分止まりで、
遅れが倍になるので採らない。

## 未解決事項

1. **将来幅予測（`predict_overtake_widths` / `has_future_width`）が効かない理由は未特定。**
   方位ノイズのせいだという従来の説明は上記のとおり否定された。
   本 ADR で速度が信用できるようになったので、次はこれを再評価する。
2. **コーナー |kappa| 0.10-0.16 の幅中断 80%** は依然として最大の失敗要因。
   本 ADR で `speed_diff` が使えるようになるため、相対速度ゲートの再検討が可能になる。
   ただし ADR-040 の教訓どおり、試行を減らす方向の変更は**成功件数**で検証すること。
3. **遅い車（実測 7.7km/h）の後ろで 13.0s / 12.1s 這っている。**
   ADR-039 の veto 例外は `FOLLOW_LEADER_MOVING_MPS = 0.5 m/s`（1.8km/h）未満しか
   対象にしておらず、7.7km/h の車はコーナー内側 veto で抜けないまま。
   閾値の見直しが候補だが、本 ADR の速度改善だけで解消する可能性もある。
4. コリドー幅 `avail_*` は**自車の幅を引いていない**（自車 1.45m 幅に対し
   中断閾値 `OVERTAKE_ABORT_WIDTH_M = 2.3`、物理限界は 1.45）。
   閾値の意味づけを整理する余地がある。
5. `is_colliding` が一度も立たず、接触回数を直接計測する手段が無い。

## 検証

`test/test_v2x_vehicle_tracker.py` の既存 14 件はそのまま通る（窓より粗い
サンプル間隔では従来挙動に落ちるため）。全体 **132 件パス**。

本番 rosbag をトラッカ本体に通した before/after は上表のとおり。
**tick 間ジッタ 9.04 → 0.86 km/h（10.5 倍）、95%tile 22.53 → 6.55 km/h。**

実走（`make dev3`）は ADR-040 の基準どおり評価する。

| 指標 | v1.3.5 本番 | 期待 |
|---|---|---|
| **成功件数 / 試行回数** | 15 / 42 | 試行を維持したまま成功件数が増える |
| コーナー成功 / 幅中断 | 26% / 63% | 改善 |
| 直線成功 | 86% | 維持 |
| 12km/h 未満の時間 | 76.3s (22%) | 減る |
| recovery 件数 | 2 | 増えないこと |

**主なリスク**: 0.125s の遅れで、急減速する相手への反応が遅れること。
ただし従来は速度自体が最大 63.6km/h と誤っていたので、遅れよりノイズの害が大きい。
