V2X Mode State Machine & Concerns Analysis

_update_v2x_mode メソッドにおける他車追従・追い越し・緊急ブレーキ状態遷移の構造解説と、実走環境で発生し得る潜在リスクの分析

1 4つのV2X制御モード一覧
NORMAL

通常走行モード。前方に干渉する車両が存在しない状態。

  • 速度制限inf (制限なし)
  • 車両半径Normal (標準)
  • 主な動作MPC最高速度走行
FOLLOWING

前走車追従モード (ACC)。車間距離と前車速度に応じて適応減速。

  • 速度制限ACC補間速度
  • 車両半径Normal (標準)
  • 主な動作車間維持・追従
OVERTAKING

追い越しモード。追従耐用時間経過後に車体半径を縮小してパスを確保。

  • 速度制限inf (制限解除)
  • 車両半径Overtake (縮小)
  • 主な動作積極的追い越し
EMERGENCY_BRAKE

緊急制動モード。TTCが危険域または至近距離に接近した際に発動。

  • 速度制限v_min_safe_mps
  • 車両半径Normal (標準)
  • 主な動作強減速・衝突回避

3 状態遷移ロジックから見える潜在的な懸念点 (Risk Analysis)
1. 緊急ブレーキ解除時の「一瞬の急加速」とチャタリング
Critical Risk
EMERGENCY_BRAKE から車間が少し開いて条件を脱出した際、直前のモードが EMERGENCY_BRAKE であるため、次のステップで NORMAL → FOLLOWING の判定に入れず、末尾の else に落ちて 1ステップだけ NORMAL (速度制限inf) になります。
原因コード: elif ... and self._v2x_mode == "NORMAL": となっており、EMERGENCY状態からの復帰先が考慮されておらず else: self._v2x_mode = "NORMAL" にフォールバックするため。
対策: 復帰時ヒステリシスを導入し、EMERGENCY解除直後は直接 FOLLOWING に安全に遷移させる。
2. 追従 (ACC) と追い越し条件の構造的矛盾
Logic Dilemma
OVERTAKING への遷移条件は min_d <= overtake_gap_min（至近距離）です。しかし、FOLLOWING 中は ACC により前車に合わせて適切に減速するため、車間距離が広がり overtake_gap_min まで詰まらない可能性が高いです。
原因構造: 「安全に車間を保つ減速ロジック」と「車間を極限まで詰めることを要求する追い越し発動条件」が相反しています。
対策: 追い越しトリガーを「車間距離」だけでなく「前車速度が目標より遅い状態が一定時間継続したか」で判定する。
3. 追い越しモードのスタック＆タイムアウト欠如
Safety Risk
OVERTAKING からの復帰条件は not is_leading_ahead and min_d >= overtake_clearance のみです。横並びのまま抜けなかったり、前車が加速して前方に離れた場合、タイムアウト機構がないため 車体半径を縮小した危険な状態のまま走行を継続 してしまいます。
原因コード: OVERTAKING 中に時間制限（overtake_timeout）や前車が遠ざかった場合のフォールバックがない。
対策: 追い越しタイムアウト（例: 5秒）を設け、失敗時は安全に FOLLOWING または NORMAL にリセットする。
4. カーブ区間での前方判定ロスト (誤加速)
False Acceleration
前方判定に固定角度（cos >= 0.5、約60度）を使用しているため、きついコーナー旋回中において前走車が自車の進行ベクトルから外れ、「前方車なし」と誤認してコーナー直前で突然フル加速するリスクがあります。
原因構造: 車両の直進ヘディング方向のみで内積を計算しており、コース参照軌道（パスのカーブ沿い）に沿った判定になっていない。
対策: 単純なベクトル角ではなく、参照軌道上のフレネ座標（$s$ 距離と $d$ 横ズレ）で前方車を判定する。
